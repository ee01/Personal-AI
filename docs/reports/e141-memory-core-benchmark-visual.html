08迁移依据判定

没有一个方案满足完整的迁移规则

规则要求：硬门全过；每个核心场景相对 A 的差值 CI 下界 ≥ −2；质量至少 +5 分或全成本降低 30%；同时满足绝对质量门、动作门和延迟门。点击方案行可以查看它进入 52 点验收集前还缺什么。

建议的下一步（是建议，不是已执行的承诺）

  1. 先修评测可解释性，不增加 LLM 费。记录客户端、run、阶段、event 水位和 generation ID；禁止没有归属的后台请求借用 active run；审核 scorer 的沉默奖励和语义支持。
  2. 开发集上对 A / C 各做两次独立重复建库，并补齐 A/C 的公平窗口对照。B 只在隔离客户端、有限工作量下查原因。两次 A/C 重复约 $13.54估算，52 点单次约 $6.29估算，合计 $19.83估算。其中 A 约 $19.31，已超出 A 剩余的 $12.43，需要缩小范围或由 E 追加预算。
  3. 核心门通过、成本归属可审、配置冻结后，再一次性跑还没碰过的 52 点验收集。
  4. 停止条件：发生一次真实越权、未来证据或删除泄漏就停；费用接近原 $50 上限就停；开发修复后核心场景仍是零召回，就终止该候选。
