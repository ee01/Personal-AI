## 2. 重评分与统计方法

本轮执行离线 rescore revision 2：97个常规/辅助 `report.json`，另8个mini报告，共105份旁路 `report.rescored.json`。主比较仅采用35份first-build；烟雾、旧全量A、重试中间态、expanded、mini互不混样。重评分不调用LLM、不覆盖原报告。[S3,S5]

四块分别报告：safety、action confusion、semantic_quality、scene_gates。**负例误触发算动作质量，不算运行安全硬门。** revision 2保留原composite，并未重新进行语义判分。原scorer用substring匹配事实，负例有引用也可能获证据分，L只判断耗时，正例沉默仍可能获L分；N也没有跨探针查重。因此composite不是人工验证的语义质量，不能证明重复率或完整用户价值。下列动作表和安全发现必须与分数一起读。[S5]

配对方法：同一probe ID对齐A与候选，先算候选−A，再在每条storyline内平均；对7个故事线均值有放回抽样，20,000次，Python Random种子141156，percentile 2.5%/97.5%，点估计取原始故事线宏平均。核心合并28对；每场景14对。整条故事线一起抽，不把正负例或四种问法视作独立样本。各故事线点数相同，宏平均等于本表点平均。

这些是**固定本次建库的条件区间**，不包括重建、模型版本、工程修复和窗口策略方差；没有多重比较校正，也不是预注册非劣效检验的最终证据。不要沿用旧单格 `storyline_ci`：其函数会在故事线内再抽单个probe，且以bootstrap均值作点估计，与本报告方法不同。

## 9. 按迁移依据裁决，以及下一轮如何花钱

此前规则为：硬门全过；**每个核心场景**相对A差值CI下界≥−2；质量至少+5分或全成本降低30%；同时满足绝对质量、动作和延迟门。当前B在相对分数条件上最接近，但在旁零召回、召回p95超标、无建库方差且七日整理未完成；C/D/E的发现CI下界低于−2。没有一家满足完整规则。[S1,S7]

| 方案 | 判断 | 进入52点验收集前提 |
|---|---|---|
| A | 保留基线，不能当已达标产品 | E裁决身份fixture；修复后冻结，补足公平对照与费用归属 |
| B | 有分数信号，先开发诊断 | 排清chat来源/队列争用，跑完七日，修在旁漏报并测水位、时延 |

| D | 暂缓正式验收 | 修8h旧证据遗漏、误报和高尾延迟；证实确有相对价值后再花费 |
| E | 暂留连续回放/整理诊断 | mini信号不能替代开发全体；修窗口依赖、误报及原生证据召回 |

**建议下一步，而非已执行承诺：**

1. 先零新增LLM费修复评测可解释性：记录客户端、run、阶段、event水位与generation ID；禁止无归属后台请求借用active run；审核scorer的沉默奖励和语义支持。版本更新后留旧分数，不能把不同rubric混作提升。
2. 在开发集对A/C做两次独立重复建库，并补A/C公平窗口对照；B只在隔离客户端、有限工作量下查因。修正阈值和动作逻辑只能用开发集。以本轮首建账面比例，两次A/C重复约$13.54，另52点单次约$6.29；合计$19.83，其中A约$19.31已超过其余量。这个外推沿用原窗口密度，尚不含新数据量、judge和修复，不作为承诺。优先用小开发子集，是否缩范围或追加A预算由E决定；本轮未花追加费用。
3. 只有核心门通过、成本归属可审、同模型同配置冻结后，才一次性跑未触碰的52点验收集。需要更多独立故事线时先预注册扩样及语义复核，不把已有56点复制成“更大样本”；至少报告建库间方差、各核心场景CI和全部失败样本。
4. 一次真实越权/未来/删除泄漏即停止候选；费用接近原$50则停；开发修复后仍核心零召回或没有明显相对收益则终止该候选补跑。不因为已搭环境而继续投入。

“不迁移”置信度高；“C更值得下一轮投入”中等，依据是8h对照稳定和原账低成本，不是质量已优胜；“B超时根因是跨服务争用”仅中低置信度，需要请求来源证据。能改变结论的新信息：独立重建后核心场景均达到绝对门、语义盲审支持、完整成本下降且非劣效CI成立、或隔离后B在质量/时延明显优于A。
