# 网页分析集成：Legacy 与未来阶段草案

*最后更新: 2026-05-20*

## 当前状态

这份文档不描述当前已上线实现。当前生效的 Chrome extension Memory Lens 以 [`docs/features/memory_lens.md`](../features/memory_lens.md) 为 source of truth。

当前 v2 边界很窄：

- 普通网页、Jira、RingCentral 消息页只做“当前页面是否有相关记忆”的被动提示。
- `v.ringcentral.com/conf/on/*` 会议页只走 Meeting Pilot 专用 surface，不展示通用网页 bubble。
- `/context-recall` 不调用 LLM，不自动写入长期记忆库，不保存完整 DOM，不保存截图，不生成回复建议。
- 用户的“有用 / 不相关”反馈会影响召回质量；单纯被动浏览不会强化 `access_count`。

## Legacy 方案

旧方案设想过“Chrome AI 快速分析 + agentThinking 深度分析 + 自动存储”的三层架构：

1. 内容脚本读取网页正文、标题、URL 与 metadata。
2. 本地模型或规则快速判断页面价值。
3. agentThinking 对高价值页面做深度分析。
4. 自动决策是否存储、通知或触发后续行动。

这套方案适合作为长期方向参考，但不应被理解为当前实现，原因是浏览噪音太大：

- 用户大量页面只是误点、预览、登录跳转、会议壳页、搜索结果页或短暂停留。
- 网页 DOM 往往包含导航、推荐、广告、评论、隐藏面板和 Personal AI 自身注入的 UI。
- 自动入库会把“看过”误当成“关心”，污染长期记忆与用户画像。
- 高隐私页面、动态 SaaS 页面和虚拟列表无法安全地用整页正文作为记忆输入。

## Future Phase：浏览作为记忆输入

未来要把网页浏览变成长期记忆输入，需要先把“候选发现”和“确认入库”拆开。

### P0：只读召回

当前阶段。网页只作为检索上下文，用于发现已有记忆的关联，不写入长期库。

核心规则：

- 被动召回不强化 `access_count`。
- 只返回 1-3 条高信号结果。
- 过滤当前 URL/self echo、负反馈、泛会议壳、calendar join boilerplate、低质 ASR、重复 meeting chunk。
- UI 必须允许关闭、站点静默、路径屏蔽、白名单模式和正负反馈。

### P1：显式保存

用户明确点击“保存这页 / 保存这段 / 记住这个决定”才写入长期库。

候选内容可以来自：

- 用户选中的文本。
- 当前可见正文摘要。
- Jira issue、Docs、RingCentral message 等站点适配器的结构化字段。
- Meeting Pilot 中已确认的 action / decision / risk。

保存前必须展示将要保存的摘要、来源 URL、可见范围和可撤销入口。

### P2：白名单候选

只在可信工作 surface 生成“可保存候选”，例如 Jira、Google Docs、RingCentral messages、内部 Wiki。

系统可以根据行为信号给候选排序：

- 停留时长、tab active 时长、滚动深度、重复访问。
- 是否复制、选择文本、打开评论、点击附件、进入 thread。
- 是否和当前项目、人、ticket、会议 action/decision 有强实体交集。
- 是否由用户从已有记忆提示点击进入。

弱信号页面只保留短期 session candidate，不进入长期库。

### P3：Opt-in Browser Memories

提供独立开关，把“浏览器记忆”与用户核心记忆分层：

- 浏览器记忆默认关闭或按站点 opt-in。
- 用户可以查看、归档、删除、按站点关闭。
- 记忆条目保存摘要、来源、时间、实体和用户交互信号，不保存完整 DOM 或截图。
- 入库前先做去噪、去重、staleness 标记和权限检查。

### P4：Governance

当浏览数据进入长期系统后，需要治理能力：

- 明确数据边界：私密浏览、支付、密码、OAuth、验证码、医疗/金融等高敏场景默认排除。
- 权限继承：跨工具检索必须尊重原工具权限。
- 可解释：每条 browser memory 都能说明为什么保存、何时保存、来自哪里。
- 可纠错：用户能标记过期、不准确、不相关，并触发降权或删除。
- 可审计：自动入库策略、模型版本、过滤原因和用户反馈要可追踪。

## v2 之后的设计问题

下一阶段不要直接做“自动存网页”，而应先做候选评估实验：

1. 在本地记录匿名化候选评分，不写长期库。
2. 对比停留时长、交互、实体重合、重复访问对“用户认为有价值”的预测能力。
3. 只在白名单工作站点展示“建议保存”入口。
4. 用用户显式保存 / 忽略 / 不再提示反馈训练排序，而不是用浏览次数直接强化 salience。

最终目标是让网页成为“记忆候选来源”，而不是让所有看过的信息自动成为记忆。
