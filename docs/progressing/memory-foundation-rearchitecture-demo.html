1 · 三个平面（memory recall core 在线零 LLM）

写平面 同步零 LLM 异步批 cheap

  1. /ingest：episode 落地 + claim 归属 + 入队，<20ms，永不阻塞
  2. scope / origin / sensitivity / injection / secret 确定性筛查
  3. 显式“记住”同步落 exact-span note + 回执；语义拆分可后台 0..N
  4. 0..N 结构化抽取：零事实是成功，失败不伪造原文首句 fact
  5. 仅独立 evidence key / provenance family 可加固；重放不加分
  6. 矛盾按 predicate policy → disputed / superseded / confirm
  7. 投影：多视图 FTS + vector；模型与量化由 P0.5 标定

睡眠平面 cheap 为主 smart 兜底

  1. 调度门：有新证据 + 预算 + 空闲；未提交的昂贵工作可取消
  2. A 生命周期算术：展示只记 exposure，不自动强化 stability
  3. B evidence-key 去重与独立来源加固（零 LLM）
  4. C 视图/周聚合可 Batch；当夜要用的 brief 走同步异步 job
  5. D 有来源的 insight；durable profile 等高责任项待确认
  6. E 图维护、GC、投影渲染（.md 不再入索引）

读平面 召回零 LLM

  1. tenant → scope → status → sensitivity → egress → injection gate
  2. InformationNeedPlanner：scene → needSlots；每个 slot 可无证据
  3. Vector / lexical / PPR / temporal / exact-rule 多通道召回
  4. 同通道按 unit 去重 → 配置化 RRF → temporal/evidence/MMR
  5. 经标注集校准的绝对 evidence gate；无证据返回 no_result
  6. Autopilot/Novelty 门控（沿用）→ destination-aware context_pack；Ask 可在其后合成

3 · 被动 Lens 检索链：现状 vs 重构

现状（为什么"有关联但不是此刻要的"）

被动检索开关默认关 → 短路到 keystone-onlyCONTEXT_RECALL_PASSIVE_SEARCH_ENABLED 未设
query = title + primaryText 截断 600 字没有"用户此刻需要什么"的建模
召回原文 400-tok chunk；LLM 摘要多数不在索引派生 .md 与原始证据同池竞争
英文 MiniLM + porter unicode61中文整句 = 1 个 token
融合 = 取最高分 + 每多一通道 +0.05无 RRF，无 reranker
十几个手调常数决定 p1/p2/hidden0.35 / 0.55 / 0.32 绝对阈值
recall_training_cases 写后无人读反馈闭环未接通

重构（RetrievalPlan）

admission gate + Scene Autopilot 判 when（沿用）
planner 按 sceneType 出 needSlots 判 whatjira_issue_reading → caliber / decision / blocker / owner
trigger question 是 unit view与正文同属 vector 通道，先按 unit 去重，不重复加分
模型与量化经 P0.5 消融后裁决 + 分词 FTS + trigram + PPR
配置化 RRF → source/time/evidence 加权 → MMR
绝对 evidence gate + 合法 no_result + 规则 sticky/cooldown
exposure 与 outcome 分开；反事实评估后才学排序

5 · 存储：先测量，再做独立 ADR

每用户向量数方案依据
P0–P3保持 per-user SQLite + pinned sqlite-vec；projection 可重建事故噪声清理后重测真实容量
索引质量不足P0.5 比较模型/float32/int8；不同版本隔离质量、延迟、体积和 recall loss 一起裁决
清理后仍有写竞争/备份/启动瓶颈另立 storage ADR，评估 ops sidecar 或索引 sidecar禁止按表数或旧噪声体积直接拆库
2026-09-03 的 1.3 GB/195 万 activation 等都是观测快照；执行前生成 evidence manifest，清理后再决定容量路线。
