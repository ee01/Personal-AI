🔧 架构说明

消息分析基于 manualConcernRules（用户规则）+ systemWatchRules（系统规则），合并为统一的 analysisRules。

RuntimeAction 定时调度决策

用户用自然语言描述的自动化动作会被拆解为一个或多个 RuntimeAction：

字段 说明
ruleRef来源规则引用，如 manual:r1a2b3
description自然语言描述（用户写的 / LLM 拆解的）
scheduledAtnull = 立即执行；有值 = 定时执行
statusqueued → running → completed / failed
executoropenclaw（统一由 OpenClaw 执行）

定时 vs 立即：所有动作的调度（包括 scheduledAt）统一由 memory-service 管理。 memory-service 在时间到达时将动作下发给 OpenClaw 执行。这样保证：

  • ✓ 定时任务有统一的存储和查看入口（动作队列页面）
  • ✓ 扩展侧不需要常驻定时器
  • ✓ OpenClaw 只负责「到时执行」，不负责「记住什么时候执行」
  • ✓ 同一条规则创建的多个定时动作可以关联查看和批量取消

📘 ManualConcernRules

  • 用户可见、可编辑
  • 默认能力：ingest, notify, digest, autoReply, followThread, automation
  • ref: manual:<id>
  • automation 字段存储自然语言描述 → LLM 拆解为 RuntimeAction

📗 SystemWatchRules

  • Runtime provider 动态生成，用户不可见
  • 只允许：ingest, answerResolution
  • 禁止：notify, autoReply, followThread, digest, automation
  • ref: outreach:<sessionId>
