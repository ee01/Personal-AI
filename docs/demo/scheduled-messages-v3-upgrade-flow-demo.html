  2. 打开 新表 Messages ，选中 A1，⌘ V
  3. 回到这里点「检查」

设计依据
  • 重新定义：原方案「只复制内容列 + 新表重算边界」→ 新方式「整行原样复制」。去重状态本来就存在 Messages 行里（Last_Exec / Exec_Log），带过来就等于带走了「今天发过没」，无需迁账本、无需新代码。
  • 预期管理：预览直接告诉用户每条消息到新表后「今天会怎样」，而不是抽象的校验通过。
  • 异常只露出 1 条（⏳），其余默认安全——希克定律，不让用户逐条审核 27 条。

一键切换

Jira 只有一条执行规则。把它的地址从旧表换成新表，这一刻起旧表自然不再被拉取——不需要停领、排空，也不会两边同时发。

将要发生的 4 处变化

  • 旧表：自动停用分钟触发器
    写入退役脚本 → 下一分钟触发器自删并在旧表留回执 · Web App 不受影响，在途确认照常
  • Jira 执行规则：领取 + 6 个确认分支换成新地址
    - …/macros/s/AKfycbx_old…/exec
    + …/macros/s/AKfycbz_new…/exec
  • Timeline 同步规则：写入新表缓存
  • 扩展：当前连接指向新表

Jira 规则更新失败（403：你不是规则 owner）。什么都没改：Jira 仍指向旧表，旧表继续发送。

设计依据
  • 重新定义：原方案「冻结 → 排空 → 最终快照 → 换址 → 激活」5 段 → 新方式「换址即交接」1 步。因为执行权只由一条 Jira 规则持有，改地址本身就是原子的执行权转移，排空交给已有的 ⏳ 暂停与 30 分钟补偿。
  • 可视化风险：把「会不会重复」从口头承诺变成一条时间轴，用户自己能看到窗口里有哪几条、为什么安全。
  • 可撤销降低焦虑：失败时明确「什么都没改」，并给人工兜底路径。
