# 项目进度仪表盘使用指南

*最后更新: 2026-07-12*

## 概述

项目进度仪表盘是 Personal AI 扩展内的项目工作台。当前版本以本地鱼骨时间线为主，用来维护项目、里程碑、任务、Jira 链接、项目健康摘要、活动级风险分、证据覆盖度、决策依据、本地查找和跨项目优先处理队列。

## 大白话运行逻辑

项目仪表盘当前首先是本地项目工作台，不是自动权威项目数据库。它会把用户维护的项目、任务、里程碑和从 Memory Service 关注项目带来的线索放在一起，用规则计算哪些项目要优先处理、哪些计划已经陈旧、哪些任务缺证据。

结果主要受这些因素影响：

1. 本地工作台数据完整度：任务 ETA、状态、里程碑、平台来源、Jira 链接越完整，风险和健康摘要越可靠。
2. Memory Service 关注项目：同步只能补齐项目入口和上下文，不能替代用户维护本地计划。
3. 证据覆盖：缺 ETA、缺 Jira、缺平台来源会显著提高“需关注”信号。
4. 时间新鲜度：过期、近 7 天到期、长期未复核会推动项目进入今日焦点。
5. 用户复核：状态草稿只有用户看过证据并记录复核后，才应降低复核压力。

## 🚀 如何访问项目仪表盘

### 方法1：从实体记忆项目入口打开（推荐）

1. 打开 `memory-exploring.html`
2. 进入项目实体列表或项目详情
3. 点击项目卡片上的仪表盘入口
4. 仪表盘会在独立窗口中打开，并带入来源项目上下文
5. 如果本地工作台已有对应项目，会置顶并高亮；如果还没有，会提示用该项目名创建本地工作台

### 方法2：直接访问HTML文件
- 直接访问：`chrome-extension://[扩展ID]/project-dashboard.html`

## 🎯 主要功能

### 1. 项目概览
- **今日焦点**：跨项目汇总阻塞、过期和 7 天内到期任务，点击后直接进入任务详情。
- **决策摘要**：首屏把最高优先级的阻塞、过期、临期、证据缺口或状态复核压成一个下一步入口，避免先扫描完整队列；当下一步是证据补全时，会进入任务详情并聚焦应先补的 ETA 或来源；当下一步是状态复核时，会直接进入“确认前先检查证据”的复核门控。
- **焦点展开**：今日焦点首屏展示优先级最高的处理项；若超过展示上限，可一键展开全部或收起。
- **活动级风险分**：今日焦点和项目内优先处理项会显示规则化风险分，结合阻塞、过期/临期、来源缺口、平台阻塞和临近里程碑解释任务优先级。
- **健康摘要**：每个项目卡片前置“正常 / 需关注 / 需处理 / 待规划”状态。
- **计划新鲜度**：每个项目会根据任务 ETA 和里程碑日期提示“计划可用 / 需复核 / 计划陈旧 / 缺时间线”，避免把过期本地计划误当成最新状态。
- **状态复核新鲜度**：每个项目会显示“已复核 / 待复核 / 复核过期 / 未复核”，把长期没有人工检查的项目纳入需关注视图。
- **状态复核队列**：今日焦点下方会列出最需要复核的项目，可先预览状态草稿和证据，再记录本次复核；项目较多时支持展开全部或收起。
- **复核前证据预览**：首屏决策摘要、项目卡片和复核队列里的复核动作都会先打开状态草稿与证据来源，确认后才记录本地复核时间，避免不看证据就把项目标成已复核。
- **证据覆盖度**：每个项目会显示活动任务的 ETA 和 Jira/平台来源覆盖情况；平台状态、平台负责人或平台 Jira 都会计入平台来源，缺证据时提示先补齐时间和来源，避免风险判断缺少依据。
- **证据补全队列**：今日焦点下方会列出缺 ETA、缺 Jira 或缺平台来源的活动任务，并显示缺 ETA+来源、仅缺 ETA、仅缺来源的构成摘要；队列按缺口严重度和风险分排序，点击即可进入任务详情并自动定位 ETA 或来源输入区，同时保留队列位置、缺口构成、排序依据和本地无写回边界回执；任务较多时支持展开全部或收起。
- **任务证据修复**：从证据补全队列进入任务详情后，会先看到 ETA、来源、风险驱动和下一步修复建议；缺 ETA 或来源时可直接定位到对应输入区，即使任务原本没有平台数据，也能按项目平台配置补充平台状态、负责人或 Jira。Jira Key 通过任务详情内的“本地 Jira 来源”表单补充，提交前校验格式，提交后显示本地保存回执；它只补当前浏览器工作台证据，不读取或写回 Jira。未保存的平台会显示“未填写来源”，不会把默认空状态当作已有证据。证据队列、首屏决策摘要、图表关键任务、数据源检查和详情页的修复按钮都会在 hover / 读屏文案里说明点击只打开本地 ETA、来源或首个任务填写位置。
- **决策依据**：每个项目会列出阻塞、过期、近 7 天到期、缺 ETA、缺 Jira/平台来源等信号，并给出建议下一步。
- **视图归类原因**：每张项目卡会解释它被归入“需处理 / 需关注 / 待规划 / 正常”的主要原因和下一步；证据覆盖不完整的项目会进入“需关注”，避免被误看成完全正常。
- **项目视图筛选**：可按“全部 / 需处理 / 需关注 / 待规划 / 正常”切换项目列表；计划陈旧、需复核或状态复核过期会归入“需关注”，缺时间线会归入“待规划”，减少多项目扫描成本。
- **本地查找**：可在当前浏览器本地快照内按项目、任务、Jira key/title、平台状态/负责人/Jira、里程碑名称或日期查找；输入多个空格分隔关键词时，会要求这些关键词同时命中同一个本地项目，但可以来自不同字段，例如 Jira key 和任务标题。输入框、清除和查看全部命中按钮会在 hover / 读屏文案里说明本地快照、当前项目视图筛选和无外部读写边界。结果回执会显示命中项目数、当前视图显示/隐藏口径、命中对象构成（项目字段 / 任务 / Jira / 平台来源 / 里程碑），并明确不会读取、同步或写回 Memory Service、Jira、GitHub、Confluence。若当前项目视图筛选隐藏了部分命中，回执和空状态可一键切到“全部”查看所有本地命中；若查找本身无命中，空状态的“查看全部项目”会清除本页查找词并恢复全部本地项目。
- **数据来源提示**：顶部常驻显示“本地工作台”边界，可从 Memory Service 关注项目补齐本地工作台；同步结果会先显示本次检查口径，再显示本地证据回执，汇总项目数、活动任务数、ETA 覆盖、来源覆盖、待规划项目和优先补齐对象，并把多个待规划项目、缺 ETA、缺来源变成有上限的可点击修复队列；点击后弹窗顶部会继续显示“本地修复入口”回执，说明只是补当前浏览器工作台，不会创建 Jira/GitHub/Confluence 任务，也不会反写 Memory Service。面板还会列出新增/匹配项目名，并用“可读取 / 暂不可用 / 未接入”区分 Memory Service 运行故障和 Jira/GitHub/Confluence 尚未接入；未接入来源的本地诊断会按来源分开，Jira 看 Jira key / 缺来源任务，GitHub 看仓库、PR、issue 或 release 映射种子，Confluence 看项目描述、里程碑和待规划项目是否适合作为空间/页面映射线索。新导入的关注项目会保持未复核状态，直到用户检查状态草稿和证据后确认。当本轮读取受限或本地证据仍待补时，顶部操作状态会用 warning 语气显示对应检查口径 / 本地证据 headline，而不是普通成功提示。
- **本地快照回执**：首次载入、手动刷新和后台刷新会显示当前本地快照读取状态；成功时显示读取项目数和时间，失败时保留旧页面数据并说明当前只是上一份本地快照，没有清空、覆盖、同步或写回 Memory Service / Jira / GitHub / Confluence。
- **关键指标**：完成任务数、阻塞任务数、过期任务数、近 7 天到期任务、下个里程碑。
- **风险优先排序**：项目列表按需处理、需关注、待规划、正常排序；同类项目优先显示阻塞和过期更多的项目。
- **优先处理项**：每张项目卡内仍会展示该项目的重点风险任务，可直接点击进入任务详情。
- **状态草稿预览**：项目卡片可打开状态更新草稿，先审阅证据来源，再复制给项目相关人；也可复制后标记本次项目状态已复核，并即时刷新复核证据。
- **项目建议**：新增项目弹窗会用输入的查找提示词向 Memory Service 请求项目名建议，结果优先匹配提示词。
- **来源项目聚焦**：从实体记忆入口打开时会保留项目 ID / 名称，优先定位对应本地项目，避免从记忆项目跳转后迷失在默认列表里。
- **鱼骨时间线**：展示里程碑、依赖、设计任务、开发任务和平台状态。
- **时间线只读排序**：时间线按任务 ETA / ID 做视图排序投影，用于定位、交替布局和拖拽锚点计算；不会在页面渲染时改写本地任务数组、导入报告顺序或导出 JSON 顺序。
- **图表概览**：每个项目卡片会把现有本地数据整理成甘特就绪度、依赖图和燃尽/完成三个轻量图表卡，并在顶部显示“图表依据”回执，说明就绪 / 待补 / 暂无数据的数量、本地 ETA / 来源覆盖、计划新鲜度边界和非外部权威同步边界；每张卡、进度条、时间点和关键任务行都会在 hover / 读屏文案里说明这是当前浏览器本地工作台的轻量图表，不确认项目状态、不发送通知、不预测完成时间或自动改期。关键任务行点击后进入任务详情，并在缺 ETA、缺来源或依赖目标无效时直接进入修复路径。甘特卡优先看活动任务 ETA；如果项目没有活动任务但已完成任务带 ETA，会把这些完成 ETA 显示为历史排期锚点，用于回看完成节奏，不代表仍有待排工作。依赖图会同时读取显式 `dep` 任务和任务级 `dependencies` 链接；当存在有效任务链时，会显示本地“关键链候选”作为最长可审任务链，提醒先复核这条链上的状态、ETA 和来源，但它不是完整关键路径计算。燃尽/完成卡会标明当前是本地任务数口径，不含工时、故事点、范围变化或速度预测；导入/导出的报告会保留这些链接，但不会把缺数据的鱼骨位置伪装成真实排期。

### 2. 数据同步与管理
- **⚡ 同步/检查数据源**：读取 Memory Service active watched projects，本地没有的关注项目会创建成待规划、未复核的工作台；同步面板会显示新增/匹配项目名。扩展端会覆盖 Memory Service 可读取和暂不可用两种路径，避免把 service worker 运行态问题误报成数据源不可用。Memory Service 读失败时会显示“暂不可用”并说明本地工作台不会被清空或覆盖；Jira/GitHub/Confluence 会显示“未接入”和不会读取的对象，避免把本地数据误认为权威快照。面板顶部会先显示“本次检查口径”，列出已读取、暂不可用和未接入跳过的来源；随后本地证据回执会告诉用户 ETA / 来源覆盖是否足够。如果同步后存在还没有任务的本地项目，即使活动任务覆盖率已满，也会显示“待规划项目”而不是“证据可用”，并为多个待规划项目提供有上限的规划按钮；规划 / 补 ETA / 补来源打开弹窗后会保留本地修复回执，确认保存前只是本页草稿，保存后也只更新当前浏览器工作台。每张来源卡再显示本地诊断，其中 Memory Service 汇总本地项目/活动任务/覆盖率，Jira 显示本地 Jira key 和缺来源任务，GitHub 显示仓库/PR/issue/release 映射种子，Confluence 显示项目描述、里程碑和待规划项目是否能作为页面/状态报告映射线索。收起面板只是隐藏本轮检查详情，保留首屏状态条和本地项目，不会取消同步、清空结果或写回外部来源。顶部操作状态只有在来源可读且本地证据可用时才用 success；来源受限或证据待补会用 warning。
- **🔄 刷新数据**：手动刷新本地缓存数据
- **刷新快照回执**：手动刷新和后台刷新只重新读取当前浏览器本地工作台；外部来源状态仍需要点击“同步/检查数据源”。如果刷新失败，页面保留上一次成功读取的本地快照并显示失败边界，避免用户把旧页面误读成刚刚同步成功。
- **后台刷新**：页面会定时静默刷新项目数据，避免打断正在查看或编辑的仪表盘状态；静默刷新失败时不会清空列表或覆盖本地数据。
- **📄 导出报告**：导出当前仪表盘项目数据为 JSON 报告
- **导出报告回执**：导出后保留文件名、导出范围、项目/任务/里程碑/Jira 数量、活动任务证据缺口和本地边界，说明 JSON 只来自当前浏览器工作台，不会同步、删除、恢复或写回 Memory Service / Jira / GitHub / Confluence。
- **📥 导入报告复核**：从 JSON 报告导入项目数据前，会先展示报告范围、项目/里程碑/任务数量、项目名预览，以及“合并导入”和“替换当前项目”分别会新增、更新、保留或移除多少本地项目；用户选择后才会写入本地工作台。
- **本地持久化**：项目、里程碑、任务和导入结果会保存到 `chrome.storage.local`

### 3. 实时状态监控
- **阻塞提示**：任务状态为 `blocked` 时，项目卡片显示“需处理”
- **ETA 提醒**：未完成任务超过 ETA 计入过期；7 天内到期计入近期关注
- **里程碑跟踪**：展示最近的未来里程碑日期
- **拖拽定位**：时间线任务拖拽后的锚点位置会保存到本地项目数据，刷新后保持位置
- **里程碑标记**：Alpha/Beta/GA 和自定义里程碑都会显示稳定圆点、外部完整标签和内部短标记，避免长名称挤出 marker

- 活动级风险分与风险驱动因素
- 项目健康视图筛选
- 本地查找栏和查找结果边界回执
- 项目卡片列表
- 项目健康摘要
- 项目计划新鲜度提示
- 项目状态复核提示
- 可展开的首屏状态复核队列
- 状态复核前的草稿 / 证据确认弹窗
- 可展开的首屏证据补全队列和缺口构成摘要
- 证据队列入口回执和修复按钮 hover / 读屏边界，说明当前点击只打开本地 ETA / 来源 / 首个任务填写位置
- 项目证据覆盖度提示
- 项目决策依据与建议下一步
- 项目视图归类原因
- 优先处理项快捷入口

- 图表卡片、进度条和时间点 hover / 读屏边界：说明本地 ETA / dependencies / 任务数口径，不代表权威同步、预测、确认状态或自动改期
- 图表关键任务行：展示每张图表判断背后的排期、阻塞、过期或缺证据任务，并可直接打开修复
- 鱼骨时间线
- 新增项目弹窗
- 来自实体记忆的项目聚焦 / 创建提示

- 任务详情编辑弹窗
- 任务详情证据修复面板、平台来源编辑区和本地 Jira 来源表单
- 状态更新草稿预览弹窗（展示本地任务 ETA、Jira、平台状态、活动风险、里程碑、复核和证据覆盖度）
- 导出报告回执（导出后展示文件名、范围、数量和不会外部写回的边界）
- 项目报告导入复核弹窗（导入前比较合并/替换影响）
- JSON 导入/导出
- 本地数据来源提示条

当前图表概览已经能基于本地任务和里程碑做轻量可视化判断。以下更完整的交互式图表仍是后续方向：

### 甘特图
- **交互式时间线**：拖拽调整任务时间
- **依赖关系显示**：可视化任务间的依赖关系
- **里程碑标记**：重要节点高亮显示
- **资源分配**：显示人员分配情况

### 依赖关系图
- **网络图布局**：展示项目间复杂依赖
- **关键路径分析**：突出显示关键依赖链
- **阻塞状态提醒**：识别和标记阻塞项
- **交互式探索**：点击节点查看详细信息

### 燃尽图
- **速度跟踪**：团队工作速度分析
- **趋势预测**：基于历史数据预测完成时间
- **里程碑对比**：计划vs实际进度对比
- **警报系统**：进度偏差自动提醒

### 风险监控面板
- **风险等级分类**：高/中/低风险可视化
- **影响评估**：量化风险对项目的影响

- **后续方向**：把本地项目与 Memory Service watched projects 做可审阅的双向同步

## 🔄 数据流程

### 输入源
1. **手动输入**：用户创建项目、里程碑和任务
2. **JSON 报告**：导入/导出仪表盘项目数据
3. **网页浏览**：Web Intelligence 和 Context Recall 识别项目相关信息
4. **Slides 分析**：Google Slides Analyzer 识别项目状态更新
5. **Memory Service 关注项目**：同步/检查数据源时补齐本地缺少的 watched projects，并显示只补齐、不删除、不反写的边界；新导入项目保持未复核，等待用户检查证据后确认
6. **后续接入**：Jira、GitHub、Confluence 等权威数据源

### 处理流程
1. **数据维护**：在仪表盘里创建/编辑项目数据，或导入 JSON 报告
2. **关注项目补齐**：同步/检查数据源时读取 Memory Service active watched projects，本地缺少的项目会新增为待规划、未复核的工作台，并在同步结果中列出新增/匹配项目名
3. **导入复核**：JSON 报告先在前端解析并计算合并/替换影响，用户确认模式后才交给后台写入。
4. **本地持久化**：保存到 `chrome.storage.local`
5. **健康计算**：按阻塞、过期、近期到期、完成数和里程碑生成摘要
6. **计划新鲜度计算**：按任务 ETA 和里程碑日期识别陈旧计划或缺时间线项目
7. **状态复核计算**：按最近一次状态复核时间识别待复核或复核过期项目
8. **证据覆盖计算**：按活动任务的 ETA 与 Jira/平台来源识别证据缺口；平台状态、平台负责人和平台 Jira 会作为平台来源证据，并生成带缺口构成摘要的可点击补全队列，进入详情时聚焦对应修复字段
9. **活动级风险计算**：按阻塞、过期/临期、来源缺口、平台状态和临近里程碑生成规则化风险分
10. **视图归类解释**：按健康、计划新鲜度、状态复核和证据缺口解释项目为什么进入当前视图
11. **本地查找过滤**：在已排序项目列表上匹配项目、任务、Jira、平台来源和里程碑文本；多个关键词会在同一个项目内做 AND 收窄，但不要求出现在同一个字段。查找结果再与当前项目视图筛选组合；查找只读当前浏览器快照，不触发外部同步。回执会拆出命中类型，并在视图筛选把命中项目隐藏时提供 `查看全部命中`，避免把本地空结果误读成外部系统没有该项目
12. **决策解释**：把风险信号、计划新鲜度、状态复核和数据缺口整理成“建议下一步”，供用户审阅
13. **决策摘要计算**：按阻塞/过期/临期任务、证据缺口构成和状态复核队列生成首屏下一步入口
14. **图表可用性计算**：按活动任务 ETA、已完成任务 ETA、里程碑日期、依赖任务 / `dependencies` 链接、来源证据和完成状态生成甘特就绪度、依赖图、燃尽/完成三个轻量图表概览；依赖图会额外从有效任务级依赖里找出最长本地任务链作为“关键链候选”；每个图表卡会列出关键任务驱动项，缺 ETA、缺来源或依赖目标无效时会给出直达任务详情并聚焦修复字段或检查目标的入口
15. **时间线排序投影**：渲染鱼骨时间线时复制任务数组后按 ETA / ID 排序，用于位置计算和视觉布局；原始本地项目数据保持不变，导入 / 导出仍保留保存时的任务顺序
16. **可视化渲染**：渲染决策摘要、项目卡片、健康摘要、活动风险、归类原因、计划新鲜度、复核队列、证据覆盖度、决策依据、本地查找回执、图表概览和鱼骨时间线

### 输出形式
1. **项目仪表盘**：首屏决策摘要、项目卡片、健康摘要、活动级风险分、视图归类原因、计划新鲜度、状态复核队列、证据补全队列、证据覆盖度、决策依据、本地查找回执、图表概览、鱼骨时间线
2. **JSON 报告**：可导出并回读导入
3. **状态更新草稿**：可在复制前预览，并附带本地证据来源
4. **后续方向**：真实数据同步、风险预测

## 🚀 快速开始

### 第一次使用
1. **安装扩展**：确保个人AI助手扩展已正确安装
2. **打开仪表盘**：从 `memory-exploring.html` 的项目入口打开，或直接访问 `project-dashboard.html`
3. **查看首屏决策摘要**：先点摘要里的下一步入口，处理最高优先级任务、证据缺口或状态复核
4. **查看今日焦点**：再确认跨项目阻塞、过期或近期到期任务
5. **必要时展开全部焦点项**：焦点超过首屏展示上限时，先展开确认是否还有更高优先级的阻塞或过期项
6. **用项目视图筛选列表**：优先切到“需处理”或“需关注”，再进入具体项目
7. **用本地查找定位对象**：输入项目名、任务名、Jira key、平台负责人或里程碑日期；如果只记得多个线索，可用空格分隔，例如 `FRESH Future`。先看命中数、多关键词收窄回执和本地边界，再进入项目或任务详情
8. **从实体记忆进入时先看来源项目提示**：已有项目会置顶；没有项目时可一键带入名称创建
9. **查看健康摘要、视图归类原因、计划新鲜度、状态复核队列、证据覆盖度和决策依据**：确认具体项目为什么需要处理或关注，以及下一步先做什么
10. **点击时间线空白处或主轴**：快速新增任务，确认标题、类型和 ETA
11. **点击任务卡片**：编辑状态、ETA、描述和 Jira 链接；新增 Jira 来源时先看表单里的本地边界提示，确认这只是给当前工作台补证据，不会同步外部 Jira。

### 日常使用
1. **同步/检查数据源**：点击“同步/检查数据源”把 Memory Service 关注项目补进本地工作台，先看“本次检查口径”确认哪些来源已读取、暂不可用或未接入跳过；再看本地证据回执里的待规划项目、ETA / 来源覆盖和优先补齐对象，可以直接点“规划项目 / 补 ETA / 补来源”进入对应本地修复位置。多个待规划项目会优先显示多个规划按钮；进入弹窗后先看“本地修复入口”回执，确认这些动作只补当前浏览器工作台，不写回外部系统。再确认新增/匹配项目名；如果看到 Memory Service “暂不可用”，先检查服务/API Key；如果看到 Jira/GitHub/Confluence “未接入”，仍以本地诊断里的 ETA、Jira key、平台来源覆盖和缺来源任务作为当前修复依据
2. **监控进度**：查看项目整体进度和关键指标
3. **切换项目视图和本地查找**：用“需处理 / 需关注 / 待规划 / 正常”筛选当前项目列表；如果知道 Jira key、负责人、任务名或里程碑日期，直接用本地查找缩小范围。多个关键词会同时收窄同一个本地项目，查找结果只来自当前浏览器快照，不代表外部系统已同步
4. **导出备份**：使用“导出全部”或项目卡片上的“导出当前项目”生成 JSON 备份；导出后先看“导出报告回执”，确认文件范围、任务数量、Jira 来源数和缺 ETA / 缺来源任务，避免把本地备份误认为外部系统同步或自动恢复。
5. **导入回读**：使用“导入报告”导入 JSON，先看复核弹窗里的项目清单和合并/替换影响；默认选择合并导入，只有确认需要移除当前本地项目时才选择替换。
6. **识别风险**：优先处理“需处理”项目中的阻塞和过期项；“需关注”也包括计划陈旧、状态复核过期或证据严重不足的项目，先更新 ETA / 里程碑、完成状态复核或补齐来源再判断风险
7. **团队协调**：先从复核队列或项目卡片打开状态更新草稿，确认左侧证据和右侧文本后再标记已复核；若证据覆盖度不足，先从证据补全队列进入任务详情，看顶部证据修复面板，必要时展开全部队列，补齐 ETA、平台状态、平台负责人或本地 Jira 来源再同步给相关人

### 图表概览使用原则

2026-06-10 对齐业内项目管理产品和软件工程 dashboard 研究后的当前原则：时间线、依赖和燃尽视图不能只给抽象分数或装饰性图形，必须能回到具体工作项。Project Dashboard 因此先把图表做成“就绪度 + 关键任务 + 修复入口”：甘特卡暴露 ETA 锚点和缺 ETA 任务，依赖卡暴露阻塞或缺来源依赖，燃尽卡暴露阻塞、过期或剩余任务。图表概览顶部会额外显示“图表依据”回执，避免把空依赖图、无活动任务、计划陈旧或来源缺口包装成“图表已就绪”。2026-07-11 复查后，图表卡片、燃尽进度条、甘特时间点、图表关键任务和图表下一步按钮都会在 hover / 读屏文案里说明当前只来自本地任务 ETA、里程碑日期、`dependencies` 和任务数口径；点击修复入口只是打开本地任务详情或本地 ETA / 来源修复位置，不确认项目状态、不发送通知、不读取或写回 Memory Service / Jira / GitHub / Confluence，不预测完成时间或自动改期。完整拖拽甘特、网络布局和趋势预测仍是后续方向，当前不把缺数据的本地鱼骨位置当成权威排期。

2026-06-14 复查后补齐依赖链边界：依赖图不再只看 `type: dep` 任务，也会读取任务上的 `dependencies` ID 列表，并在导入 / 导出 JSON 报告时保留这些链接。如果链接指向当前项目里不存在的任务或里程碑，图表卡会显示“依赖目标无效”并打开对应任务让用户检查，而不是静默把这条链从依赖图里丢掉。

2026-06-21 复查后补齐燃尽口径边界：Jira / Agile 里的 burndown 通常需要剩余 effort、story point 或工时口径，而当前本地工作台只有任务条目、状态和 ETA。燃尽/完成卡因此会直接显示“任务数口径”，并说明它不包含工时、故事点、范围变化或 velocity 预测。

2026-06-25 复查后补齐依赖链优先级：Microsoft Planner 的 critical path 和 Linear 的 timeline dependencies 都说明依赖视图不能只判断“有没有依赖”，还要帮助用户先看哪条链。当前实现不做完整关键路径算法，而是在本地 `dependencies` 能形成有效任务链时显示“关键链候选”：这是最长可审任务链，点击进入链末任务复核状态、ETA 和来源；里程碑依赖仍计入目标有效性，但不会被伪装成任务链节点。

2026-07-03 复查后补齐链上历史完成口径：如果最长本地依赖链里包含已完成的上游任务，依赖卡会显示 `链上已完成 N`，关键链 driver 也会说明这些节点只是历史前置，不代表仍有待排工作。这个提示不改变关键链算法，不读取 Jira/GitHub/Confluence，也不会自动预测完工日期。

2026-06-26 复查后补齐本地查找命中线索：本地查找回执不只显示命中项目数，还会拆出命中来自项目字段、任务、Jira、平台来源或里程碑；如果查找有命中但当前“需处理 / 需关注 / 待规划 / 正常”视图没有显示，回执可直接切到“全部”查看命中，避免把筛选隐藏误读成外部系统没有该对象。

2026-07-08 复查后补齐当前视图口径：本地查找回执会直接写明当前“全部 / 需处理 / 需关注 / 待规划 / 正常”视图显示了多少个本地命中，以及还有多少命中被项目视图筛选隐藏；切到“全部”只恢复本地快照内的命中，不触发外部读取或同步。

2026-07-12 复查后补齐本地查找控制点边界：输入框、清除按钮、回执里的 `查看全部命中` 和空状态按钮都会在 title / aria-label 里说明当前只是过滤本地快照、保留或清除本页查找词、项目视图是否仍生效，以及不会读取、同步或写回 Memory Service / Jira / GitHub / Confluence。查找无命中时，空状态的 `查看全部项目` 会同时清除 query 并切到全部视图，避免按钮看似恢复列表但仍被无命中查找词挡住。

2026-06-28 复查后补齐多关键词查找：本地查找不再把 `FRESH Future` 这类输入当作必须连续出现的一整段文本。空格分隔的关键词会在同一个本地项目内同时匹配，可以分别落在 Jira key、任务标题、负责人或里程碑等字段；回执会说明本轮按几个关键词收窄，仍不读取外部项目系统。

2026-06-19 复查后补齐本地查找：多项目 dashboard 的问题不只是摘要是否准确，还包括能否快速回到“那个 Jira / 那个 owner / 那个里程碑”。当前先实现本地快照内的文本查找和结果回执，匹配项目、任务、Jira、平台来源和里程碑；它和项目视图筛选组合使用，但不会触发外部读取或同步。

2026-06-29 复查后补齐甘特历史锚点：如果项目没有活动任务，但已完成任务保留 ETA，甘特卡会显示“已完成 ETA 可作历史锚点”和完成任务 driver。这个视图只帮助回看本地完成节奏；它不会把项目标成仍有待排工作，也不会读取 Jira/GitHub/Confluence 或生成 effort、velocity、趋势预测。

### 导入报告使用原则

2026-05-31 对齐 Jira / Asana / Linear 的项目状态面板和 PMIS 信息质量研究后，导入报告被视为会改变本地项目事实的高信任操作，不再用浏览器原生确认框一跳完成。当前实现会先解析报告并显示合并/替换两种模式的影响：合并保留本地项目、更新同 ID 项目并新增缺失项目；替换会移除报告外的本地项目。导入只写当前浏览器本地工作台，不会反写 Memory Service 或外部项目系统。

2. **批量操作**：同时处理多个任务或里程碑
3. **趋势分析**：基于历史数据分析项目趋势
4. **智能推荐**：AI驱动的项目优化建议

### 长期愿景（6个月以上）
- 成为完整的智能项目管理平台
- 支持自定义工作流和模板
- 集成更多企业级工具
- 提供深度学习驱动的项目优化建议

## 💡 使用技巧

### 提高效率
1. **设置快捷键**：为常用功能设置Chrome快捷键
2. **定制提醒**：根据项目特点设置智能提醒
3. **批量导入**：使用CSV或API批量导入项目数据
4. **模板复用**：保存常用的项目模板以快速创建新项目

### 最佳实践
1. **定期维护**：每周清理和更新项目信息
2. **团队协作**：确保团队成员及时更新状态
3. **数据质量**：保持数据的准确性和完整性
4. **持续优化**：根据使用情况调整配置和流程

---

**注意**：当前仪表盘数据是扩展本地维护的项目工作台数据，不是 Jira/GitHub/Confluence 的权威快照。健康摘要、活动级风险分、计划新鲜度、证据覆盖度和视图归类原因都是规则化提示，不是 ML 风险预测。

## 参考方向

- [Atlassian Jira dashboards](https://support.atlassian.com/jira-cloud-administration/docs/use-dashboard-gadgets/) 强调用小组件把项目进度、阻塞和到期工作集中呈现。
- [Atlassian Home Dashboard Insights](https://support.atlassian.com/platform-experiences/docs/get-dashboard-insights-in-home-dashboards/) 把 dashboard 摘要、最多 3 个 notable insights/anomalies 和 AI 可靠性边界放在同一个入口；Personal AI 的查找回执沿用“先说明范围和限制”的原则。
- [Atlassian Rovo Ops AI risk assessment](https://support.atlassian.com/jira-service-management-cloud/docs/assess-potential-risks-to-your-changes-with-rovo-ops/) 强调风险等级需要配套可审阅证据、数据来源和人工判断边界。
- [GitHub Projects roadmap](https://docs.github.com/en/enterprise-server%403.16/issues/planning-and-tracking-with-projects/customizing-views-in-your-project/customizing-the-roadmap-layout) / [status updates](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/sharing-project-updates) 把里程碑、日期标记和项目状态放进可扫描视图。
- [Asana project status](https://help.asana.com/s/article/project-progress-and-status-updates?language=en_US) / [portfolio views](https://help.asana.com/s/article/portfolio-views) 强调状态、负责人、到期时间、里程碑、风险摘要和 portfolio 级视图。
- [Linear project updates](https://linear.app/docs/initiative-and-project-updates) 和 [Microsoft Planner premium](https://support.microsoft.com/en-gb/office/advanced-capabilities-with-premium-plans-in-planner-6cdba2aa-da06-4e08-be4c-baaa4fda17ba) 都把健康状态、进度变化、里程碑、依赖、关键路径和定期更新提醒放在项目决策路径里。
- [Jira burndown](https://www.atlassian.com/agile/tutorials/burndown-charts) 和 [Asana chart styles](https://help.asana.com/s/article/chart-styles?language=en-US) 都把燃尽图视为剩余工作/完成趋势视图；Personal AI 当前只在本地任务有足够 ETA 与完成状态时展示任务数完成率，避免把本地任务条目伪装成 effort / velocity 预测。
- [Linear project dependencies](https://linear.app/docs/project-dependencies)、[Planner premium dependencies / Timeline](https://support.microsoft.com/en-US/Planner/teams/advanced-capabilities-with-premium-plans-in-planner) 和 [Microsoft Planner critical path](https://support.microsoft.com/en-us/planner/show-the-critical-path-of-a-plan) 都把依赖关系放在时间线旁边处理；当前实现先把阻塞依赖、缺来源依赖、无效依赖目标和本地关键链候选显性化，再引导用户补证据或检查目标。
- [GitHub project updates](https://docs.github.com/en/enterprise-cloud@latest/issues/planning-and-tracking-with-projects/sharing-project-updates) 和 [Linear initiative/project updates](https://linear.app/docs/initiative-and-project-updates) 都把状态、目标日期、历史更新和人工发布放在可审阅路径里；[Linear Project Graph](https://linear.app/docs/project-graph) 明确需要足够 issue 数据才生成图表和预测。本地数据源诊断沿用这个边界：先说明本地证据是否够，再考虑真实外部同步。
- [Rocketlane project management dashboard guide](https://www.rocketlane.com/blogs/project-management-dashboard) 把 dashboard 定位成决策信号层，而不只是任务列表；本地查找因此优先支持能直接定位决策上下文的 Jira、owner、任务和里程碑关键词。
- 软件工程数据质量研究指出，敏捷/软件项目数据常见缺口包括不可访问、不完整、不一致、低精度和跨系统语义不一致；状态面板因此要把来源覆盖和缺口显性化，可参考 [agile data management challenges SLR](https://link.springer.com/article/10.1007/s10664-025-10630-4)、[GitHub mining perils](https://www.microsoft.com/en-us/research/publication/an-in-depth-study-of-the-promises-and-perils-of-mining-github/) 和 [Project Intelligence](https://research.google/pubs/project-intelligence/)。
- 用户中心 dashboard 研究也提醒，数据质量、用户预期和不断变化的需求会共同影响 dashboard 可用性；因此同步后的空项目必须继续显示为待规划证据缺口，而不能被总体 ETA / 来源覆盖率掩盖，可参考 [Data Quality, Mismatched Expectations, and Moving Requirements](https://arxiv.org/abs/2209.06363)。
- Dashboard、PMIS 和项目风险研究通常建议控制信息过载，把异常、下一步动作、数据新鲜度和活动级风险贡献放在首屏，可参考 [dashboard evaluation framework](https://arxiv.org/abs/2009.04792)、[dashboard information load 研究](https://www.sciencedirect.com/science/article/pii/S0926580523002893)、[PMIS 多项目决策研究](https://www.sciencedirect.com/science/article/abs/pii/S0263786311000688) 和 [Activity Risk Index](https://arxiv.org/abs/2406.00078)。
- Gantt/项目可视化研究提醒，传统甘特图在大项目中容易丢失历史和趋势，需要概览、异常和 details-on-demand 配合使用，可参考 [3D project task visualization empirical study](https://www.sciencedirect.com/science/article/pii/S016412121600008X)、[Project Tube Maps vs Gantt Charts](https://kar.kent.ac.uk/14324/) 和 [Gantt visualization task taxonomy](https://arxiv.org/abs/2408.04050)。
