# 项目进度仪表盘使用指南

*最后更新: 2026-05-07*

## 概述

项目进度仪表盘是 Personal AI 扩展内的项目工作台。当前版本以本地鱼骨时间线为主，用来维护项目、里程碑、任务、Jira 链接、项目健康摘要和跨项目优先处理队列。

## 🚀 如何访问项目仪表盘

### 方法1：从实体记忆项目入口打开（推荐）

1. 打开 `memory-exploring.html`
2. 进入项目实体列表或项目详情
3. 点击项目卡片上的仪表盘入口
4. 仪表盘会在独立窗口中打开

### 方法2：直接访问HTML文件
- 直接访问：`chrome-extension://[扩展ID]/project-dashboard.html`

## 🎯 主要功能

### 1. 项目概览
- **今日焦点**：跨项目汇总阻塞、过期和 7 天内到期任务，点击后直接进入任务详情。
- **焦点截断提示**：今日焦点首屏展示优先级最高的处理项；若超过展示上限，会明确提示剩余未展示数量。
- **健康摘要**：每个项目卡片前置“正常 / 需关注 / 需处理 / 待规划”状态。
- **数据来源提示**：顶部常驻显示“本地工作台”边界，明确 Jira/GitHub/Confluence 自动同步尚未接入。
- **关键指标**：完成任务数、阻塞任务数、过期任务数、近 7 天到期任务、下个里程碑。
- **风险优先排序**：项目列表按需处理、需关注、待规划、正常排序；同类项目优先显示阻塞和过期更多的项目。
- **优先处理项**：每张项目卡内仍会展示该项目的重点风险任务，可直接点击进入任务详情。
- **状态草稿预览**：项目卡片可打开状态更新草稿，先审阅证据来源，再复制给项目相关人。
- **项目建议**：新增项目弹窗会用输入的查找提示词向 Memory Service 请求项目名建议，结果优先匹配提示词。
- **鱼骨时间线**：展示里程碑、依赖、设计任务、开发任务和平台状态。

### 2. 数据同步与管理
- **⚡ 检查数据源**：明确显示 Jira/GitHub/Confluence 尚未接入真实同步，避免把本地数据误认为权威快照
- **🔄 刷新数据**：手动刷新本地缓存数据
- **后台刷新**：页面会定时静默刷新项目数据，避免打断正在查看或编辑的仪表盘状态。
- **📄 导出报告**：导出当前仪表盘项目数据为 JSON 报告
- **📥 导入报告**：从 JSON 报告导入项目数据，支持合并或替换当前项目列表
- **本地持久化**：项目、里程碑、任务和导入结果会保存到 `chrome.storage.local`

### 3. 实时状态监控
- **阻塞提示**：任务状态为 `blocked` 时，项目卡片显示“需处理”
- **ETA 提醒**：未完成任务超过 ETA 计入过期；7 天内到期计入近期关注
- **里程碑跟踪**：展示最近的未来里程碑日期
- **拖拽定位**：时间线任务拖拽后的锚点位置会保存到本地项目数据，刷新后保持位置
- **里程碑标记**：Alpha/Beta/GA 和自定义里程碑都会显示稳定圆点、外部完整标签和内部短标记，避免长名称挤出 marker

## 当前界面

目前仪表盘提供：

- 跨项目今日焦点队列
- 项目卡片列表
- 项目健康摘要
- 优先处理项快捷入口
- 鱼骨时间线
- 新增项目弹窗
- 新增任务弹窗（点击时间线空白处、主轴或箭头时，会带入最近里程碑日期作为 ETA）
- 任务详情编辑弹窗
- 状态更新草稿预览弹窗（展示本地任务 ETA、Jira、平台状态和里程碑证据）
- JSON 导入/导出
- 本地数据来源提示条

以下高级可视化仍是后续方向：

## 🔧 技术特性

### 智能数据收集
- **被动收集**：网页浏览时自动识别项目相关信息，并回链到记忆界面
- **用户输入**：支持手动添加和编辑项目信息
- **后续接入**：真实 Jira/GitHub/Confluence API 同步

### 类人脑记忆机制
- **本地项目工作台**：仪表盘数据保存在 `chrome.storage.local`
- **长期记忆**：项目实体和上下文由 Memory Service 管理
- **后续方向**：把本地项目与 Memory Service watched projects 合并

### 当前限制
- 项目数据仍保存在当前浏览器本地
- 多设备同步、多人协作和冲突解决尚未实现
- Jira/GitHub/Confluence 真实同步尚未实现，“检查数据源”只用于说明当前数据来源状态

## 🎨 界面设计

### 响应式布局
- **桌面优化**：1200x900 像素窗口体验最佳
- **移动适配**：小屏幕会压缩项目卡片和健康摘要布局

### 用户体验
- **直观导航**：清晰的功能分区和操作流程
- **快速操作**：一键同步、导出、刷新
- **实时反馈**：操作状态和结果即时展示
- **边界可见**：不需要先点击检查按钮，也能知道当前数据不是 Jira/GitHub/Confluence 权威同步快照

## 🔄 数据流程

### 输入源
1. **手动输入**：用户创建项目、里程碑和任务
2. **JSON 报告**：导入/导出仪表盘项目数据
3. **网页浏览**：Web Intelligence 和 Context Recall 识别项目相关信息
4. **Slides 分析**：Google Slides Analyzer 识别项目状态更新
5. **后续接入**：Jira、GitHub、Confluence 等权威数据源

### 处理流程
1. **数据维护**：在仪表盘里创建/编辑项目数据，或导入 JSON 报告
2. **本地持久化**：保存到 `chrome.storage.local`
3. **健康计算**：按阻塞、过期、近期到期、完成数和里程碑生成摘要
4. **可视化渲染**：渲染项目卡片、健康摘要和鱼骨时间线

### 输出形式
1. **项目仪表盘**：项目卡片、健康摘要、鱼骨时间线
2. **JSON 报告**：可导出并回读导入
3. **状态更新草稿**：可在复制前预览，并附带本地证据来源
4. **后续方向**：真实数据同步、风险预测

## 🚀 快速开始

### 第一次使用
1. **安装扩展**：确保个人AI助手扩展已正确安装
2. **打开仪表盘**：从 `memory-exploring.html` 的项目入口打开，或直接访问 `project-dashboard.html`
3. **查看今日焦点**：先处理跨项目阻塞、过期或近期到期任务
4. **查看健康摘要**：确认具体项目是否需处理或需关注
5. **点击时间线空白处或主轴**：快速新增任务，确认标题、类型和 ETA
6. **点击任务卡片**：编辑状态、ETA、描述和 Jira 链接

### 日常使用
1. **检查数据源状态**：点击“检查数据源”确认当前仍为本地工作台数据
2. **监控进度**：查看项目整体进度和关键指标
3. **导出备份**：使用“导出全部”或项目卡片上的“导出当前项目”生成 JSON 备份
4. **导入回读**：使用“导入报告”导入 JSON，按提示选择合并或替换
5. **识别风险**：优先处理“需处理”项目中的阻塞和过期项
6. **团队协调**：先预览并复制状态更新草稿，再用任务详情里的平台负责人和 Jira 链接追踪责任人

### 高级功能
1. **自定义筛选**：根据时间、状态、人员筛选信息
2. **批量操作**：同时处理多个任务或里程碑
3. **趋势分析**：基于历史数据分析项目趋势
4. **智能推荐**：AI驱动的项目优化建议

2. **团队协作**：确保团队成员及时更新状态

## 参考方向

- [Atlassian Jira dashboards](https://support.atlassian.com/jira-cloud-administration/docs/use-dashboard-gadgets/) 强调用小组件把项目进度、阻塞和到期工作集中呈现。
- [GitHub Projects roadmap](https://docs.github.com/en/enterprise-server%403.16/issues/planning-and-tracking-with-projects/customizing-views-in-your-project/customizing-the-roadmap-layout) / [status updates](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/sharing-project-updates) 把里程碑、日期标记和项目状态放进可扫描视图。
- [Asana project status](https://help.asana.com/s/article/project-progress-and-status-updates?language=en_US) / [portfolio views](https://help.asana.com/s/article/portfolio-views) 强调状态、负责人、到期时间、里程碑和风险摘要。
- Dashboard 和 PMIS 研究通常建议控制信息过载，把异常、下一步动作和数据新鲜度放在首屏，可参考 [dashboard evaluation framework](https://arxiv.org/abs/2009.04792) 和 [PMIS 多项目决策研究](https://www.sciencedirect.com/science/article/abs/pii/S0263786311000688)。
