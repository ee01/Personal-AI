# 自定义提示词与用户上下文

## 功能概述

Personal AI 提供一个独立的配置页，用于维护消息分析、项目分析的自定义关注点，以及用户的角色、团队、工作重点和分析偏好。分析流程会把这些配置作为用户偏好注入到 LLM 提示词中，用来影响关注重点和输出风格。

入口：
- 记忆入口规则窗口（`topic-modal.html`）顶部的“自定义提示词与上下文”按钮会打开 `prompt-config.html`
- Options 页面顶部提供同名入口，方便从扩展设置直接进入长期偏好配置
- 配置页支持重新加载、保存、融合到用户画像、重置默认
- 配置页支持暂停参与分析注入，也可以只暂停“自定义提示词”或“用户上下文”其中一个来源；关闭后会保留已保存内容，但真实分析与预览不会读取被暂停的长期偏好来源。

## 大白话运行逻辑

这个功能决定“哪些用户自定义背景可以被带进 AI 请求”。用户写下来的提示词不会天然到处生效，而是要经过开关、作用域和注入位置控制。

结果主要受这些因素影响：

1. 总开关和作用域开关：关闭某个注入开关后，对应提示词即使存在也不会进入运行时。
2. 场景匹配：消息分析、项目分析、网页分析、Compose Assist 等入口会读取不同范围的上下文。
3. 用户确认程度：用户显式写入的配置优先级高于系统推断的软提示。
4. 提示词长度和冲突：过长或互相矛盾的提示词会降低模型执行稳定性，后续应靠预览和分区降低风险。
5. 下游消费者：真正是否生效取决于调用方有没有接入对应提示词包，而不是 Options 页面是否显示。

## 当前能力

### 自定义提示词

- 消息分析提示词：用于消息重要性判断、规则匹配、行动建议等分析。
- 项目分析提示词：用于项目、会议、文档类分析的风险、依赖、里程碑等关注点。
- 每类提示词都有独立启用开关；启用后必须填写内容。
- 单个提示词限制为 1500 字符；保存、恢复和分析注入都会清洗过长或空白内容，避免长期偏好吞掉过多上下文。
- 配置页提供消息分析、项目分析的常用示例，可一键插入并自动启用对应提示词，降低从空白文本框开始配置的成本。
- 点击快速插入示例后，提示词区会显示“示例草稿”回执：说明这只是当前页面草稿，保存前不会进入真实分析、写入本机配置或备份到记忆服务；如果当前生效预览范围看不到这类提示词，会提供切到消息 / 项目预览的快捷入口。
- 配置页顶部显示生效摘要：当前启用的提示词范围、有效上下文信号数量、安全提示数量和本机历史版本数。
- 配置页顶部提供“参与分析注入”开关，默认开启；其下还有自定义提示词、消息提示词、项目提示词、用户上下文来源开关，便于只排查某一类长期偏好或某个分析作用域的影响。
- “参与分析注入”总开关或“用户上下文”来源开关相对已生效基线变更但尚未保存时，开关区会显示待保存回执：当前页面预览会按草稿开关重算，但真实消息、项目、会议和文档分析仍读取已生效基线；保存后才会写入本机配置并尝试更新记忆服务恢复备份。
- 页面有未保存修改时会显示待保存的配置区块摘要，例如消息提示词、团队信息或分析偏好，避免多标签页编辑后不知道本次会提交什么。
- 页面有未保存修改时会按当前预览范围显示“保存影响”：注入体积、提示词范围、上下文信号、安全提示和回执状态会从已保存版本变成什么，帮助用户保存前判断这次改动会不会真正影响消息/项目分析。
- 生效预览会显示当前读取的是“已保存配置”还是“草稿预览”。草稿状态会明确说明真实消息、项目、会议和文档分析仍读取上次保存的配置；只有点击保存后才写入本机并尝试备份到记忆服务。
- 页面顶部会常驻显示“已生效基线”回执，标明当前真实分析读取的是默认配置、本机配置、记忆服务备份，还是本机保存且已备份的版本，并展示保存时间、本轮加载时间和本机优先 / 记忆服务仅作恢复备份的边界。
- 配置页会显示清洗后的“生效预览”，并与真实分析注入共用上下文构建逻辑，避免用户看到的字段和模型实际收到的字段不一致。
- 生效预览支持一键复制当前范围的清洗后注入文本。复制后会显示回执，说明复制的是已保存基线还是未保存草稿，并明确这只是审计文本，不会保存配置、触发真实分析或写入/备份到记忆服务；如果当前范围没有会进入真实分析的注入文本，复制操作会显示空预览回执且不写入剪贴板；如果复制后切换全部 / 消息 / 项目范围、继续编辑或保存导致当前预览变化，回执会变成旧快照，提示剪贴板仍是上一次复制的范围，必须重新复制才会更新。
- 生效预览可在“全部 / 消息 / 项目”之间切换；消息视图只展示消息分析会收到的上下文和消息提示词，项目视图复用项目/会议/文档类分析会收到的上下文和项目提示词，避免预览把不相关偏好误显示成当前任务会注入。
- 生效预览的范围切换旁会显示“范围依据”回执：`全部` 是审计并集，不代表某一次真实分析会同时注入消息和项目专项上下文；`消息`、`项目` 才分别对应真实消息分析和项目 / 会议 / 文档分析的运行时范围。用户上下文页签的本轮范围总览也复用同一口径。
- 生效预览和用户上下文页签里的“全部 / 消息 / 项目”范围按钮会在 hover 与读屏标签里说明点击只会切换当前页面预览范围，不会保存配置、触发真实分析、融合画像、写入本机配置或备份到记忆服务；有未保存草稿时也会说明真实分析仍读取已生效基线。
- 生效预览会按当前预览范围显示清洗后注入体积和粗略 token 估算；如果当前范围没有可注入内容，会显示 scope-aware 空状态，说明是全局/来源暂停、当前范围不匹配，还是只有默认值/空内容，帮助判断长期偏好是否真的生效。
- 生效预览旁会显示注入回执，逐项标出用户上下文、消息提示词、项目提示词是“注入 / 不在范围 / 暂停 / 空”，让用户不用展开原始 prompt 也能判断当前分析会读取哪些长期偏好。用户上下文回执会进一步拆出基础、消息、项目上下文数量，并提示哪些范围因当前预览未被注入。
- 用户上下文页签内会直接显示“注入路径”回执：个人、团队、工作、沟通信息属于基础上下文，会进入全部 / 消息 / 项目预览；分析偏好会拆成消息专项和项目 / 会议 / 文档专项。这个页签回执会跟随当前生效预览范围，说明本页字段是进入当前消息 / 项目分析，还是保留但不进入当前范围；如果全局或用户上下文来源已保存为暂停，字段仍保留但当前分析不会读取；如果只是未保存草稿暂停，页签会说明当前页面预览已暂停但真实分析仍读取已生效基线。
- 用户上下文页签首屏会显示“用户上下文本轮范围”总览，按当前全部 / 消息 / 项目预览统计本轮会读取的基础、消息、项目信号，以及保留但不进入当前范围的专项信号。同一回执内可以直接切换全部 / 消息 / 项目预览，切换只改变当前页面预览和注入回执，不会保存配置、触发真实分析、融合画像或写入记忆服务；草稿未保存时真实分析仍读取已生效基线。
- 用户上下文字段如果疑似包含 API key、token、password、private key 或 webhook，页面会在生效预览区和对应页签显示“用户上下文敏感提示”。保存或融合前需要确认这些内容不是可用凭据，或已经改成不可执行引用；确认只允许写入本机配置并尝试做记忆服务恢复备份，不会执行、验证或用这些值调用外部系统。
- 每个提示词编辑区会标明实际作用范围，避免用户误以为消息分析和项目/会议/文档分析都会注入同一段内容。
- 如果启用的提示词疑似包含覆盖系统/开发者规则、索取隐藏提示词、改变 JSON 返回结构、把偏好写成永久记忆/上级提示词，或使用混淆拼写/隐藏编码来绕过规则的语句，页面会给出提示；即使当前提示词来源或作用域暂停注入，保存或融合前仍需要用户显式确认这些语句只按低优先级偏好处理，因为内容会随长期配置保留，重新开启后才会进入真实分析。
- 风险提示确认会绑定当前注入状态；如果用户先在“已暂停”状态确认保留风险提示词，之后重新开启自定义提示词来源或消息/项目作用域，保存前需要按“会进入真实分析注入”的状态重新确认。保存影响也会区分安全提示是 `注入` 还是 `暂停`，避免把“仅保留”误读成“已允许激活”。
- 保存或融合被安全提示拦截时，页面会显示持久的“保存 / 融合阻塞”回执：说明本次没有保存草稿、触发真实分析、写入或备份到记忆服务；融合场景也不会写入用户画像。回执会指向提示词或敏感上下文页签，让用户确认低优先级边界、改写风险语句或删除可用凭据后再继续。
- 保存配置和融合到用户画像共用顶部操作区，但进行中状态会分开显示：保存时说明正在写入本机并尝试备份，融合时说明正在请求把用户上下文融合到用户画像；融合完成前不代表用户画像已更新，也不会触发真实分析。
- 顶部主操作按钮会在 hover 与读屏标签里显示当前点击边界：重新加载只会读取本机配置 / 记忆服务恢复备份，保存才会写入本机并尝试备份，融合会先保存未保存草稿再请求用户画像融合，重置默认只改页面草稿；加载、保存、融合、未确认安全提示和未保存草稿状态下都会说明哪些动作暂不可用以及不会触发真实分析。
- 提示词编辑区会就近显示安全提示和非阻塞优化建议，例如提示词过短、接近长度上限、两类提示词完全相同，或内容疑似放错作用范围。

注入策略：
- 自定义内容会被包裹为“用户长期偏好”。
- 自定义内容会放入结构化的 `user_preference_data` 标签中，并明确声明它不能覆盖系统规则、工具安全边界或 JSON 返回格式要求。
- 未启用或空内容不会注入。
- 关闭全局注入开关时，自定义提示词和用户上下文都不会注入；只关闭自定义提示词来源时仍可注入用户上下文，只关闭用户上下文来源时仍可注入启用的提示词。自定义提示词来源开启时，还可以单独暂停消息分析提示词或项目分析提示词，保留内容但不进入对应真实分析与预览。

### 用户上下文

配置页目前覆盖：
- 个人信息：姓名、邮箱、职位、部门、地点、时区
- 汇报关系：直接主管、关键干系人
- 团队信息：团队名称、使命、规模、成员、工作时间和时区
- 工作关注：关注点、业务领域、关键指标、风险承受度
- 沟通偏好：受众类型、沟通风格、文化背景、语言偏好、汇报格式
- 分析偏好：消息关注领域、忽略话题、紧急关键词、项目风险因素和成功标准

`src/services/userConfigPreview.ts` 负责把当前 UI 的数据结构转换为简短上下文，并同时服务配置页预览和 `src/agentThinking.ts` 的真实分析提示词注入，例如直接主管、团队成员、关键指标、紧急关键词等。
真实注入会按分析范围裁剪用户上下文：消息分析注入消息关注领域、忽略话题和紧急关键词；项目、会议、文档类分析注入项目风险因素、成功标准和项目审查周期；个人身份、团队、工作关注和沟通偏好作为跨范围基础信号保留。这样可以减少长期上下文对当前任务的噪声和 token 占用。
用户上下文也会被包裹进低优先级的 `user_preference_data` 数据块，并声明它只能作为身份、团队、工作和沟通偏好使用，不能覆盖系统规则、工具边界或返回格式。这样即使某个上下文字段里误填了“忽略系统规则”或粘贴了结束标签，也只会作为普通偏好数据处理，真实注入和生效预览保持一致。

保存前会清理数组里的空项、裁剪多余空白，并移除没有实际姓名/职责信息的空干系人或团队成员，避免分析提示词里出现空值噪声。
用户上下文的单项文本会限制到 200 字符，列表类字段最多保留 20 项，避免把长期偏好配置变成无边界的上下文注入。

### 存储与恢复

保存路径以本机为主：
- 主存储：`chrome.storage.local`
- 备份：memory-service 的 profile item，类型为合法的 `preference`
- 配置项 key：`personal_ai_independent_user_config`
- 注入开关、来源开关和消息/项目提示词作用域开关随独立配置一起保存和备份，旧配置没有这些字段时按开启处理。

保存时先写本机，再尝试写记忆服务备份。备份失败不会阻塞本机保存。读取时优先使用本机配置；如果本机没有配置，会尝试从记忆服务恢复。

交互保护：
- 重新加载前会确认是否丢弃未保存修改。
- 融合到用户画像前会先保存当前页面配置，避免显式偏好和本机配置不一致。
- 融合到用户画像会复用保存前校验；如果当前提示词存在安全提示，按钮会提示先确认低优先级偏好边界。
- 如果存储配置缺少姓名或邮箱，页面会用当前登录用户信息做空值回填，避免初始化顺序导致个人信息偶发为空。
- UI 默认值不会单独作为显式偏好注入；只有用户填写或改动出的有效内容才会进入预览和分析提示词。
- 每次保存会在本机保留最近 10 个清洗后版本，可从配置页恢复历史版本，再保存生效。版本历史保存和读取都会按内容去重，忽略 `lastUpdated` 等同步时间戳，避免重复版本挤占回滚列表。
- 版本历史会显示本次保存变更的配置区块，例如消息提示词、项目提示词、团队信息或分析偏好；用户恢复前可以先判断这版为什么值得回滚，而不是只看到最终快照摘要。
- 版本历史会在每条记录上显示“恢复前影响”：如果恢复后再保存，这版相对当前已生效基线会如何改变当前预览范围的注入体积、提示词范围、安全提示和回执状态；点击恢复本身仍只载入页面草稿，不会保存、触发真实分析或写入记忆服务。
- 从版本历史恢复后，页面会显示持久的“恢复草稿”回执，说明恢复的是哪一版、当前预览读取的是恢复草稿，真实分析仍使用上方已生效基线；只有再次保存后才会写入本机并尝试备份到记忆服务。
- 点击“重置默认”只会把当前页面恢复成默认草稿，并保留当前姓名 / 邮箱身份字段；保存前真实分析、本机配置、记忆服务备份和用户画像都不会改写。页面会显示持久的“重置草稿”回执，说明当前预览显示默认草稿、真实分析仍读取已生效基线，用户可以重新加载丢弃草稿或保存后才让默认配置生效。

## 技术实现

主要文件：
- `src/modals/prompt-config.tsx`：配置界面、校验、保存和恢复
- `src/services/userConfigSanitizer.ts`：提示词长度、空值和用户上下文字段的共享清洗逻辑
- `src/services/userConfigPreview.ts`：生效预览、真实上下文注入、风险提示和本机版本历史 helper
- `src/services/UserConfigStore.ts`：独立用户配置的 memory-service upsert/read helper
- `src/services/UserProfileMessageHandler.ts`：处理配置存储、读取和融合消息
- `src/agentThinking.ts`：把自定义提示词和用户上下文注入分析提示词
- `tools/verify-custom-prompts.ts`：目标验证脚本
- `tools/verify-custom-prompts-e2e.mjs`：扩展页面端到端验证脚本

关键修复：
- memory-service profile API 只允许 `fact/preference/habit/interest/constraint`，因此独立配置使用 `preference` 存储，而不是无效的自定义 item type。
- 记忆服务备份使用 upsert，避免每次保存生成多个活跃配置项。
- 分析流程兼容当前配置页的 `stakeholders/teamInfo.members/analysisPreferences.messageAnalysis` 结构。
- 通用提示词构建不再把 `{ enabled, content }` 对象拼成 `[object Object]`。
- 配置页补齐团队、沟通偏好和关键干系人的编辑路径，并避免表单更新时直接修改嵌套状态。
- 配置页标题改为“自定义提示词与上下文”，入口收敛到记忆入口规则窗口，避免 popup 主操作区重复出现配置按钮。
- 保存、memory-service 备份和分析注入共用清洗逻辑，过长提示词会被限制到 1500 字符，空数组项不会进入提示词。
- 用户自定义提示词注入时使用共享的结构化标签 helper 隔离，并要求模型忽略试图覆盖角色、工具、安全边界或返回格式的语句。
- 配置页新增清洗后生效预览、风险提示和最近 10 个本机保存版本的恢复入口。
- 默认下拉值不再制造“空配置也有偏好”的误注入；版本历史 fingerprint 也不再因为保存时间变化而重复。
- 生效预览和真实分析注入改为复用 `buildUserContextPreferenceSection`，并补充记忆污染类风险提示，降低偏好被误读为系统级长期指令的风险。
- 风险提示命中的自定义提示词需要在页面上确认后才能保存或融合，降低误粘贴 jailbreak / prompt injection 片段后直接进入长期偏好的概率。
- 生效预览和真实分析注入同时复用 `buildCustomPromptPreferenceSection`，避免安全包裹、标签转义或长度标记在 UI 与真实 prompt 中出现漂移。
- 生效预览新增注入字符数和粗略 token 估算，配合共享清洗层限制用户上下文长文本与数组长度，降低长期偏好挤占任务上下文的风险。
- 风险提示新增混淆拼写和“解码后执行隐藏指令”类检测，覆盖更接近业内 prompt injection 测试样例的误粘贴场景。
- 配置页新增 `detectPromptImprovementHints`，把提示词管理产品常见的“质量漂移/重复/作用域不清”问题提前反馈给用户，但不阻塞保存。
- 历史版本读取路径也会执行 fingerprint 去重，保证旧存储里的重复版本不会挤掉更早但内容不同的回滚点。
- 历史版本新增 `changedLabels` / `changeSummary`，保存时会和上一条有效历史配置比较，并在配置页显示“首次保存”或“变更：...”摘要，补齐提示词版本审计和回滚前判断。
- 配置页保存前复用同一套变更判断逻辑显示“未保存变更：...”，把 prompt 管理产品常见的 save-review 心智前移到本机轻量配置流程。
- 新增全局偏好注入开关和提示词/上下文来源开关；共享预览层和真实 `agentThinking` 注入路径都按同一组开关裁剪长期偏好。
- 新增消息提示词/项目提示词作用域注入开关；生效预览、风险提示计数、注入体积估算和真实 `agentThinking` 注入路径都会按同一组作用域开关裁剪长期偏好，便于排查某一类提示词对分析结果的影响。
- 用户上下文与自定义提示词预览都按消息/项目分析范围裁剪，配置页生效预览也提供相同范围切换；会议、文档和通用项目类分析会复用项目范围上下文与项目提示词，并修复了上下文块与分析正文标题之间缺少换行导致内容粘连的问题。
- 生效预览新增 `buildPreferenceInjectionReceipt` 回执层，用同一套开关、作用域和清洗结果解释当前范围中每个偏好来源为什么注入、被排除、暂停或为空。
- 用户上下文回执新增 scope-aware breakdown：同一套裁剪 helper 会统计基础、消息、项目上下文信号，并在消息/项目预览里明确显示另一个范围有多少项没有进入本轮分析。
- Options 页面新增 Prompt Config 入口，并用 E2E 覆盖从设置页打开 `prompt-config.html` 的路径，避免长期偏好配置只能从记忆入口规则窗口发现。
- 空预览不再只显示泛化“没有可注入偏好”，而是复用注入回执给出原因和下一步，例如切换预览范围、打开对应注入开关或补充提示词/用户上下文。
- 保存前新增 `buildPreferenceChangeImpact` 回执，把当前草稿和已保存配置按预览范围比较，显示 token/字符变化、提示词作用域变化、上下文信号变化、安全提示变化和注入回执变化；保存成功后该回执消失，历史版本仍记录区块级变更摘要。
- 保存影响现在也比较清洗后的预览正文，所以同长度、同风险状态的提示词改写不会被误报成“注入效果不变”。页面同时显示草稿/已生效回执，避免把未保存预览误读为真实分析已经生效。
- 用户上下文注入现在和自定义提示词一样带低优先级数据边界：预览、真实分析 prompt 和注入回执都会说明它是 `user_context` 数据块，并会转义用户字段里误粘贴的结束标签，避免把上下文字段误读成可执行上级指令。
- 配置页新增 `buildUserContextSectionReceipt` / `buildUserContextSectionReceipts`，在每个用户上下文页签显示字段所属范围、暂停状态和 `user_context` 低优先级边界，避免用户只有切到生效预览后才知道字段会影响哪类分析。
- 用户上下文页签回执会读取当前生效预览范围：基础上下文会说明进入当前预览，专项分析上下文会拆出当前消息 / 项目预览已注入和未注入的信号，避免“注入”状态掩盖当前范围其实不会读取某类专项偏好。
- 用户上下文页签新增 `用户上下文本轮范围` 总览，复用 `buildUserContextScopeBreakdown` 汇总当前预览会读取的基础 / 消息 / 项目信号和被范围排除的专项信号，并在首屏说明总览不会保存、触发真实分析、融合画像或写入记忆服务。2026-06-23 补充同屏范围切换按钮，用户在填写个人 / 团队 / 工作 / 沟通 / 分析上下文时不需要滚到生效预览区，也能快速核对消息分析和项目 / 会议 / 文档分析会读取哪些长期上下文。
- 配置页新增 `buildPreferencePreviewScopeReceipt` 范围依据回执：`全部` 明确是审计并集，消息 / 项目明确是运行时范围，避免把全量审计预览误读成单次 LLM 请求会收到的真实上下文。
- 配置页新增持久化基线来源回执：加载、保存成功、备份失败后都会保留当前已生效配置来自哪里、何时保存 / 加载，以及草稿是否尚未进入真实分析。
- 生效预览新增复制审计回执：复制当前范围的清洗后 prompt 只用于人工检查或外部对比，不会顺手保存草稿、触发分析或制造记忆服务备份。
- 复制审计回执会绑定当时的预览范围、文本快照和草稿 / 基线状态；页面预览变化后显示“旧快照”，避免用户误以为剪贴板已经跟随当前预览自动更新。
- 空生效预览下点击复制会显示“无内容”回执，说明当前范围没有会进入真实分析的注入文本、本次没有写入剪贴板，也没有保存、触发分析或写入/备份到记忆服务。
- 版本历史恢复新增草稿回执：恢复历史版本只把旧版本装回编辑器和生效预览，不会立即替换真实分析基线、写入本机或更新记忆服务备份；用户继续编辑、重置、重新加载或保存后该恢复回执会清除。
- 用户上下文新增敏感凭据提示：共享预览层会扫描当前表单和旧结构字段里的明显 secret 形态，普通邮箱/姓名不触发；页面会把提示显示在生效预览区和对应页签，并在保存/融合前要求用户确认这些值不是可用凭据或已改成引用。
- 保存前安全确认现在覆盖“已启用但暂停注入”的风险提示词；预览区会标明它当前不会进入真实分析，但仍会随配置保存，后续重新开启注入后才生效。
- 风险提示确认不再跨注入状态复用：暂停状态下的确认只能证明用户同意保留这段低优先级偏好，重新开启注入来源或作用域后必须重新确认；保存影响行会显示 `1 条注入` / `1 条暂停` 这类状态差异。
- 保存 / 融合安全门禁新增阻塞回执，把“没有写入、没有触发分析、真实分析仍读已生效基线”和下一步恢复动作显示在主操作区下方，避免安全阻断被误解成系统卡住或静默保存失败。
- 保存 / 融合进行中也拆成独立回执和按钮文案，避免融合用户画像时仍只显示“保存中”，从而把 profile mutation 等待态误读成普通配置保存。
- 重置默认新增草稿回执和更准确的确认文案：重置只改变当前页面草稿，保存前不会改写真实分析基线、本机配置、记忆服务备份或用户画像；手动编辑、恢复历史、重新加载或保存会清除该回执。
- 快速插入提示词示例后新增就近“示例草稿”回执，补齐按钮动作、预览范围和保存边界：插入会启用对应提示词但只改页面草稿，保存前不会影响真实分析或任何持久存储；当前预览范围排除该提示词时，可以直接切到对应范围核对保存影响。
- 参与分析注入总开关和用户上下文来源开关新增待保存回执：暂停或重新开启只会先改变当前页面草稿与预览，真实分析仍读已生效基线；保存后才会改变本机配置并尝试备份。
- 版本历史列表新增恢复前影响预览，复用保存影响比较口径，让用户在恢复旧版本前先看到该版本保存后会改变的提示词范围、注入体积、安全提示和回执状态，同时明确恢复按钮不会立即写入真实分析基线。
- 生效预览和用户上下文首屏范围切换按钮新增 `title` / `aria-label` 边界：按钮本身会说明目标范围、审计并集 / 运行时范围区别、草稿未保存状态和无保存 / 无真实分析 / 无画像融合 / 无本机或记忆服务写入副作用，避免只依赖切换后的周边回执。
- 顶部重新加载、保存配置、融合到用户画像和重置默认按钮新增 `title` / `aria-label` 边界：按钮文案会随加载、保存中、融合中、安全提示未确认、未保存草稿和无草稿状态变化，明确本次点击会读取、保存、备份、融合或只生成页面草稿，以及不会立即触发真实分析。

## 业内参考

- ChatGPT Custom Instructions / Memory：偏好可编辑、可删除，可关闭或用临时聊天绕过，并作为未来对话上下文使用。
- Claude Memory / Claude Code memory：强调个人偏好、项目约定和工作上下文的显式管理，并提供可选/分域的记忆边界。
- LangSmith、PromptLayer、Humanloop：提示词管理通常需要版本、评估、追踪和回滚；本功能对应补强的是本机历史的变更摘要，而不是完整远端发布流。
- Prompt injection 相关研究和 guardrail 文档：用户可编辑提示词必须被降级为偏好或数据，不能覆盖系统指令。
- LLM agent memory privacy 和长期记忆污染研究说明，持久化上下文里的用户/外部输入可能在后续会话继续影响模型，甚至造成隐私泄露；因此用户上下文不仅要做低优先级标签隔离，也要在疑似凭据进入长期配置前给出可见提示。
- Prompt management 研究也指出，提示词容易出现格式不一致、重复和质量漂移，因此历史、去重和可验证回滚是基础能力。
- Personalization 相关研究强调用户偏好能提升主观任务效果，但也会引入隐私、过拟合和偏好污染风险，因此页面优先做显式可见、可恢复、可撤销的轻量偏好管理。
- AlpsBench 等长期个性化评测进一步说明，显式记忆机制不等于稳定偏好对齐；因此页面要把本轮实际读取的偏好来源显示成回执，而不是只显示“已开启”。
- LaMP、CoPS 等个性化检索/生成研究都强调从用户画像中选择与当前任务相关的少量 profile/context 项，而不是把完整历史或完整偏好无差别塞入 prompt；本功能当前采用按分析范围裁剪的轻量版本。
- Prompt registry / prompt ops 产品通常在保存或发布前展示版本差异、运行影响和回滚路径；本功能当前采用本机轻量版，只比较真实注入体积、作用域、风险和回执，不引入远端发布流。

本功能当前优先保证“可控、可恢复、不会阻断分析”。后续再考虑云端版本历史、导入导出、效果对比和按消息/项目等功能作用域的更细粒度开关。

## 当前限制

- 记忆服务备份是恢复用途，不是完整的多端冲突解决系统。
- 融合到用户画像目前保存为显式偏好配置，但还没有做结构化拆分和逐项确认。
- 版本历史仅保存在本机，还没有云端多端历史、版本 diff 和 A/B 评估。
- 注入暂停已经能按提示词来源、用户上下文来源、消息提示词和项目提示词拆分；用户上下文会按消息/项目分析范围裁剪，但更细的单条上下文项开关暂未实现。基线来源回执只说明当前页面已保存配置的来源和备份状态，不是多端冲突合并记录。
