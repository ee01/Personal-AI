# Google Slides 项目分析器

最后更新: 2026-07-13

## 功能概述

Google Slides 项目分析器用于在 Google Slides 页面中识别项目表格或项目列表，抽取项目/Jira 工单、状态、负责人、赛道和备注信息，并结合 Jira 与历史上下文生成可人工确认的更新建议。

当前入口：

- Google Slides 页面内容脚本会在工具栏添加 `分析项目` 按钮。
- 如果 Google Slides 加载较慢或重建工具栏，页面按钮会自动补回。
- 工具栏入口支持键盘聚焦与 Enter/Space 触发；hover / 读屏先说明本次只生成审阅快照和可写字段建议，不会立即写回 Slides，也不会反写 Jira 或 Memory Service；OAuth 失败会在 Slides 页面给出错误提示。
- 工具栏入口在授权/分析过程中会进入忙碌状态，重复点击只提示等待，并说明不会二次授权、重复分析、打开多份结果页或写回外部系统。
- 扩展 popup 在 Google Slides 页面打开时显示 `分析 Slide 项目信息并更新`。
- 分析结果在 `slides-analysis.html` 中展示，用户勾选后才会写回幻灯片。

## 大白话运行逻辑

这个功能先读 Slides 里的文字和表格，识别哪些内容像项目状态，再把建议写回变成“待复核队列”。用户确认后才把字段写回对应 slide/table/cell。

结果主要受这些因素影响：

1. Slide 内容结构：表格、标题、项目名、owner、日期、状态越规范，识别越稳。
2. 字段定位是否可靠：行列索引、shape id、文本范围必须能对应到真实 Slides 元素，否则进入 skipped/blocked。
3. 风险判断语义：高风险、阻塞、关闭状态、否定表达需要区别处理，不能只靠关键词。
4. 复核选择：默认字段级复核，用户可以选择哪些字段写回；未选字段不应被写入。
5. Google API 写回结果：部分成功时要保留 skipped reasons 和 blocked fields，方便人工接管。

## 当前能力

- 读取当前 Google Slides 演示文稿，并优先分析当前 slide。
- 解析阶段会把实际分析范围带到结果页，包括已分析 slide 数、目标 slide id、低置信/多表合并/整份 deck fallback 等提醒，避免用户误以为所有内容都被稳定识别。
- 结果页首屏显示 `分析快照回执`，绑定 presentation、目标 slide、本页收到时间、项目/建议/可写字段/默认选择/当前选择数量，并说明它不是 deck 实时监听；如果 Slides 已被编辑、切页或表格重排，需要回到 Google Slides 重新点击 `分析项目`。
- 结果页会在“分析范围与提醒”里显示 `范围判定回执`，直接说明本轮是当前 slide 抽样还是整份 deck 覆盖、解析提醒数量，以及查看/筛选/复制不会重新分析或写回。
- 支持表格型、文本/列表型内容；同一 slide 上多个可信项目表格会合并分析；表格备注列可识别 Comments、Highlights、Actions、Next steps 等常见命名；常见 PM 周报表头如 RAG/Health、DRI、Workstream、Updates/Blockers 也会映射到状态、负责人、赛道和备注；低置信或复杂结构可使用 LLM fallback。
- 自动提取 Jira key（支持 `AIT2-11063` 这类带数字项目前缀），并查询 Jira 状态、负责人、优先级和截止日期等上下文。
- 文本/列表型 slide 会合并同一 Jira key 在标题、列表项和段落抽取中的重复结果，避免结果页出现重复项目建议。
- 生成状态、负责人、赛道、备注的更新建议，并展示置信度、关键发现和风险统计。
- 只对用户勾选的字段调用 Google Slides `batchUpdate` 写回，避免自动覆盖 slide 内容。
- 写回表格单元格时使用明确的删除范围和插入位置；备注建议会按行剔除已存在内容，避免多行建议中部分重复的内容被再次追加。
- 结果页会使用同一套备注去重逻辑，只展示和提交新增备注行；完全重复的备注建议会从可写字段中排除并提示已存在。
- 状态、负责人和赛道在结果页展示与写回前都会做大小写与空白归一化比较，避免仅格式差异触发无意义更新或默认勾选。
- 只有识别到可写表格列的建议才进入可勾选写回；结果页会提示无法写回的字段。
- 写回完成后结果页会显示实际写入字段数并清空选择，避免重复提交。
- 如果写回部分成功但有字段被跳过，完成面板会保留具体跳过原因，方便用户回到 Slides 补列、修定位或手动处理。
- 写回完成面板会保留 Google Slides 已确认写回的字段、变更摘要和来源/复核状态，作为用户离开结果页前的字段级回执；本地预检跳过项不会混入已确认写回字段列表。
- 部分成功时会把跳过原因和本次提交字段匹配成“人工接管清单”，保留建议值、来源依据、下一步处理方式，并支持复制给后续手动处理；复制清单会逐项标出 `可重选` / `人工核对` 接管方式，并同时说明哪些字段已被 Google Slides 确认写回、哪些字段只是本地跳过未进入 batchUpdate、哪些对象不会写入 Jira / Memory Service。
- 跳过/失败接管清单复制后会保留 `跳过清单复制回执` / `失败清单复制回执`，说明复制到本机剪贴板的接管项数量、可重选与人工核对范围；失败清单逐项保留整批未确认状态；复制不会自动重试、不会写回 Slides、不会反写 Jira 或 Memory Service。
- 部分成功的原子批次摘要按实际进入 Google Slides `batchUpdate` 的字段计算，同时保留原始选择范围，避免用户把本地跳过字段误读成已写入。
- 如果 slide/table/row 定位失效，跳过原因会按已提交字段保留，避免只报项目级失败而无法和回执、建议值、来源依据对上。
- 跳过原因可以按项目、字段名、英文 API 字段别名或 slide/table/行/列目标定位回提交字段，避免部分成功时因为错误文案不一致退化成无法接管的项目级提示。
- 如果 Google Slides 或本地预检返回的跳过原因无法匹配到具体字段，完成面板会隐藏字段级“已确认写回”列表，只保留写回数量、原子批次边界和未匹配接管项，避免把未写入字段误标为已落地。
- 如果成功回包的写回数量少于本次提交字段数，但没有给出足够跳过原因，结果页会把差额转成“未返回具体跳过原因”的人工接管项，隐藏字段级确认列表，并提示先回到 Slides 核对实际内容。
- 部分成功面板会把唯一匹配到字段的跳过项标为可重选，并在每个跳过项上区分 `可重选` / `人工核对`；用户可以只恢复这些字段到本地提交范围后再决定是否分批重试，未匹配原因仍只进入人工核对，不会猜测字段。
- 在部分成功面板里重选跳过字段后，页面会把旧完成面板标成上一批回执，并在新的写回预览里显示 `接管中回执`，说明当前只是本页重新选择、尚未重新提交或写回。
- 写回请求如果长时间没有返回结果，结果页会退出“正在更新”状态并提示用户回到 Slides 确认实际写入情况。
- 结果页初始加载如果无法收到 Google Slides 页面返回的数据，会显示恢复提示并允许重新请求数据。
- 结果页的重新请求数据只会向原 Google Slides 页面索取当前分析结果快照；页面会显示重新请求回执，说明这不会重新分析 deck、不会写回 Slides，也不会反写 Jira 或 Memory Service。
- 结果页支持按全部、已选、需复核、风险和无法写回筛选建议，并可一键恢复“高可信且有来源证据”的默认选择或清空选择，方便批量审阅。
- 结果页在恢复默认选择、清空选择或仅保留当前筛选字段后，会保留 `选择范围回执`，说明这只改变结果页本地提交范围，不会重新分析 deck、不会写回 Slides、Jira 或 Memory Service。
- 筛选结果为空时，结果页会按当前视图说明为什么没有卡片、下一步可以恢复默认/查看全部/切到相关视图，并明确这些操作只改本地选择状态，不会重新分析 deck、写回 Slides、Jira 或 Memory Service。
- 筛选视图如果隐藏了已勾选字段，底部写回区会提示隐藏选择数量，并允许跳到已选视图或仅保留当前视图内的选择，避免误写回；写回区也会提示已选字段中有多少来源充分、多少仍需人工复核。
- 写回区会预览即将写回的项目、字段、变更摘要和字段级来源/复核原因；筛选隐藏的已选字段也会计入预览和溢出提示。
- 写回区会显示 `写回决策回执`，把提交字段/项目数、当前筛选可见与隐藏选择、来源充分与人工纳入字段、未选/无法写回/仅风险项不进入批次，以及不会反写 Jira 或 Memory Service 的边界放在应用按钮前。
- 结果页的筛选、恢复默认、清空选择、复制复核清单、隐藏选择处理、应用写回，以及跳过/失败接管按钮都会在 hover 和读屏说明点击后果：哪些只是本页筛选/本机剪贴板/本地选择，哪些才会提交 Google Slides 写回请求。
- 写回决策回执、复制出来的复核清单和提交中回执都会带同一条 `快照基准`：说明这批字段依据哪一次 presentation / 目标 slide 分析快照，应用前不会重新读取 deck、复查当前表格行列或确认协作编辑；如果用户已经切页、改表格或同事更新，需要先回 Slides 重新分析。
- 写回决策回执、复制出来的复核清单和提交中回执也会显示 `快照年龄`，提醒这份分析快照已经在结果页停留多久；如果 deck 已切页、表格重排或协作编辑，需要先回 Slides 重新分析再写回。
- 快照年龄会每分钟刷新，并在用户回到结果页或标签重新可见时立即刷新；超过 10 分钟会升级为重新分析提示。此刷新只更新本页本地展示，不会重新读取 deck、重新分析或写回任何系统。
- 写回预览、复制清单和完成/失败回执会保留字段级写入目标，包括 slide、table、行和列，用户离开结果页前能核对这批字段到底会落到哪里。
- 写回预览会明确提示本次字段会组成一个 Google Slides 原子 `batchUpdate`；任一 API 子请求无效时整批不会写入。
- 写回区支持复制当前已选字段的复核清单，包含 presentation id、项目/字段、变更、来源依据和复核标签，方便应用前交给同事或自己二次核对。
- 复制复核清单后会保留 `复核清单复制回执`，说明复制的字段/项目/隐藏选择/人工纳入数量、剪贴板本机边界，以及选择变化后旧清单不会自动更新。
- 写回请求进行中会显示 `提交中回执`，列出已发出的字段/项目范围、presentation id、原子批次和等待边界；字段勾选、筛选、全选和复核队列会锁定，避免等待 Google Slides API 回包时改变界面选择但实际 payload 已发送。
- 如果 Google Slides API 拒绝整批写回或结果页超时，失败面板会保留“失败接管清单”：列出未确认写入的字段、目标单元格、来源依据、失败原因和下一步，并支持复制，避免用户离开页面后手抄或误以为部分字段已经落地。
- 失败接管清单里的每个字段项都会直接标出 `整批未确认`，让用户在长列表中逐项扫读时也能看出这批字段没有任何字段级写入确认；复制清单也保留同一状态。
- 默认勾选会检查到字段级来源：同一条高可信建议里，只有状态、负责人、赛道或备注各自具备直接来源的字段才会默认写回，缺少直接来源的字段保留为人工勾选。
- 字段 checkbox、字段复核队列 checkbox 和项目全选 checkbox 都带控制点回执，读屏和 hover 能看到建议值、目标 slide/table/行列、默认/复核状态，以及“只改本页本地选择、不会立即写回或重新分析”的边界。
- 赛道建议会保留来源理由并参与字段级默认勾选，避免高可信赛道更新因为缺少可见依据而被误判为需复核。
- 结果页会把需复核字段和无法写回字段汇总到字段复核队列；可写的复核字段可直接在队列中勾选，阻塞字段会显示缺失列原因。
- 字段复核队列会直接展示字段变更预览和来源/复核依据，用户不必回到项目卡片才能判断是否勾选。
- 无法自动写回的字段会在项目卡内展示建议值和来源/复核原因，方便用户补列或手动更新。
- 项目卡片的复核提示会列出具体需人工确认的字段，避免把“部分字段缺少直接来源”误读成整条建议都没有来源。
- 结果页会把风险、阻塞、未关闭高优先级和未关闭逾期 Jira 项目汇总到风险焦点区，并在项目卡片内展示风险依据；`No risk`、`Not done` 这类否定/未完成表达和已完成状态不会被误算为风险。
- Jira 来源卡片会展示工单最近更新时间；没有安全 http(s) URL 的 Jira key 只作为普通来源文本展示，不生成假链接。
- Jira 来源卡片不会把带 userinfo、token、session、OAuth code、签名或 credential 参数的 URL 渲染成可点击链接；此时只展示 Jira key 和 `链接已隐藏` 回执，避免把 tokenized / signed source URL 当作普通来源链接传播。
- 结果页会在写回前展示“分析范围与提醒”，把解析范围和结构识别警告前置到用户审阅路径里。
- Google Slides 页面工具栏入口会做单次运行保护；授权或分析尚未完成时不会再次发起分析。
- 只有风险但没有字段差异的项目也会作为风险关注卡片展示，但不会计入可写回字段或默认选择。
- 分析摘要和结果页共用同一套风险识别逻辑，避免同一项目在顶部统计和详情卡片里风险结论不一致。
- 项目风险等级会归一化处理：`medium` 和旧版 `normal` 计入需要关注，`high` / `critical` 计入严重风险，`low` 才计入正常。

## 用户体验原则

- AI 只生成草稿建议，最终是否写回由用户确认。
- 从 Slides 工具栏触发分析时，入口必须明确显示正在授权或正在分析；重复点击不能重复请求 OAuth、重复跑分析或打开多个结果页。
- 工具栏入口的 idle、授权中、分析中和启动超时状态都要提前说明：点击只进入分析快照/审阅结果页路径，不会直接应用写回，也不会反写 Jira 或 Memory Service。
- 高置信且有 Jira、历史上下文或明确理由的建议可以默认选中；低置信或缺少可见来源的建议需要用户主动审阅。
- 结果页区分“字段有直接来源默认选中”和“字段需复核未默认选中”，并显示已选字段数量，降低误写回风险。
- 需要人工判断的字段应集中成队列，并尽量在队列内完成勾选或跳转筛选，避免用户逐张项目卡查找复核点。
- 真正会改变提交范围的 checkbox 必须在控件自身说明本次只是在结果页本地选择字段；用户还需要点击应用并等待 Google Slides 回包，不能把勾选动作误读成已写回。
- 字段复核队列必须包含待写入值和字段级依据，避免用户只凭项目名、字段名和低可信提示做选择。
- 项目级复核提示必须指出具体字段和原因，避免用户为了一个未默认字段重新怀疑整条建议。
- 用户可以先筛到需复核或无法写回项集中处理，也可以随时恢复高可信默认选择，避免长列表审阅时迷失当前选择状态。
- 空的筛选视图不能只显示泛化空状态；需要说明当前视图无匹配、没有发生重新分析或外部写回，并给出返回全部/恢复默认/查看相关视图的下一步。
- 在任一筛选视图里执行写回前，页面必须明确提示是否还有隐藏的已选字段，用户可以先查看全部已选或把选择收敛到当前视图。
- 写回前必须让用户看到具体字段级变更预览和对应来源/复核原因，而不只展示数量；写回进行中不能继续改勾选状态或切换筛选视图，并要看到这只是等待 Google Slides 回包、不是写回完成。
- 写回前的决策回执必须把“这次会写哪些字段、哪些字段只是当前筛选隐藏、哪些字段是人工纳入、哪些对象不会写入”放在同一区域，避免用户把 filtered view 当成完整提交范围。
- 写回前必须看到分析快照年龄；结果页停留时间越长、deck 越可能发生协作编辑或结构变化，就越应该回 Slides 重新分析后再提交。
- 字段级写回回执必须说明写入目标，至少覆盖 slide、table、行和列；如果定位缺失，要在预览或跳过/失败路径中显式暴露，不让用户凭项目名猜测会改哪一格。
- 写回前的复核信息应可复制成轻量清单，保留字段级证据和人工复核标签，方便在真实周报协作里先审后写。
- 复制复核清单必须是可见的本机 handoff：页面要说明复制不是应用、不会写回或重新分析，且复制后如果用户改变选择，剪贴板里的旧清单需要重新复制才可信。
- 用户手动勾选低可信或缺少直接来源的字段后，写回前仍应看到需复核数量，避免把人工接管后的字段误认为系统默认安全项。
- 多表项目页会合并展示各个可信项目表格，避免用户以为整页已检查但实际只处理了一个分组。
- 分析范围、低置信或 fallback 提醒必须直接展示在结果页，而不是只写到 console；用户在批量勾选前应先知道本次分析覆盖了当前 slide 还是整份 deck，并看到它只是审阅快照、不是重新分析或写回。
- 结果页需要先交代本轮分析快照身份，包括 presentation、目标 slide、收到时间和当前选择状态；如果用户已经改过 deck，页面不能暗示这些建议仍是实时状态。
- 用户可以先查看风险焦点或风险筛选，再在项目卡片内核对风险依据，减少项目周报页里查找阻塞项的成本。
- 没有字段可写回的风险关注项需要明确标注为“仅关注”，避免用户误以为有隐藏写回动作。
- 项目统计必须和风险筛选一致，避免中等风险项目被误显示为正常进行。
- 同一项目只呈现一张合并后的建议卡，减少重复勾选和重复写回的审阅负担。
- 每条建议展示来源证据摘要；没有可见来源时，页面会明确提示保持未勾选直到人工确认。
- 来源证据要尽量带上新鲜度线索，例如 Jira 最近更新时间；不能打开的来源不要伪装成可点击链接。
- 来源链接必须 fail closed：非 http(s)、含凭据 userinfo 或 credential-like 查询/fragment 参数的 URL 只能作为普通来源文本出现，并要说明链接被隐藏；用户可以回 Jira / Slides 原页面核对，结果页不复制或打开这类敏感 URL。
- 备注字段只呈现和写回新增信息，并在当前备注已有部分内容时明确提示“只会追加新增行”，避免用户在反复分析同一张项目 slide 时清理重复 note。
- 对缺失表格列导致不能自动写回的建议，结果页直接说明原因，不让用户卡在不可操作的勾选区。
- 无法写回字段必须保留可人工接管的信息，包括建议值和对应来源/复核原因，避免用户只知道缺列但不知道应填什么。
- 无效或缺少行/列定位信息的写回请求会返回失败或跳过提示，不保持“正在更新”的悬挂状态，也不会把无效 `cellLocation` 发给 Slides API。
- 部分成功的写回结果必须说明被跳过字段的具体原因，避免用户只看到数量但不知道如何修复。
- 写回成功后仍要保留确认写回字段回执，方便用户核对哪些字段已进入并完成 Slides API 请求，尤其是包含人工复核字段或部分跳过时。
- 部分成功时，跳过字段必须从确认写回列表和确认批次字段数中剥离，只出现在跳过原因和人工接管清单里。
- API 写回失败时要保留“本次未完成字段”和原子批次说明，避免用户误以为部分字段已落地。
- 整批失败和超时都要给可复制的人工接管清单；清单必须明确 Google Slides 没有确认这批字段写入，用户需要先核对 slide/table/行列/权限，再决定是否整批重试。
- 整批失败的字段项也要逐项显示 `整批未确认`，不能只依赖面板标题或复制文本来表达写入状态。
- 部分成功后的跳过项要能直接接管：用户应看到是哪一个项目/字段、建议值、来源依据、为什么跳过，以及下一步是补列、修定位、检查权限还是重新分析；复制出去的清单也必须保留“已确认写回 / 本地跳过未写入 / 可重选或人工核对 / 不会反写外部系统”的边界。
- 复制跳过/失败接管清单后不能只依赖短暂 toast；页面必须留下本机剪贴板回执，说明复制没有重选字段、没有自动重试、没有执行额外写回。
- 行、表格或 slide 定位失效也必须作为字段级跳过项进入人工接管清单，不能退化成无法匹配的项目级错误。
- 即使跳过原因来自英文 API/运行时文案，只要能唯一对上 slide、table、行列目标，也要回到对应字段级接管项；不能要求错误文案必须包含固定中文字段名。
- 无法匹配到字段的跳过原因不能让结果页继续展示完整“已确认写回字段”列表；此时只能确认 Google Slides 返回的写回数量，并把字段级接管交给人工清单。
- 如果只有聚合写回数量、没有足够的字段级跳过原因，也不能猜测哪些字段已写入；页面只能展示聚合确认数，并把缺失原因的差额交给人工核对。
- 已匹配跳过字段可以被一键重选；部分成功清单及复制清单必须逐项显示 `可重选` 或 `人工核对`，且重选只改变结果页本地选择状态，不会自动重试、不会写回 Slides，也不会反写 Jira 或 Memory Service。
- 重选跳过字段后，上一批 Google Slides 确认/跳过结果必须和当前本地重选范围分开显示，避免用户把旧成功回执误读成新字段已经落地。
- Google Slides 页面或结果页通信异常时，结果页会保留当前建议和勾选状态，方便用户确认后重试。
- 直接打开结果页或父窗口丢失时，页面会说明需要从 Google Slides 重新触发，避免用户停在无限加载状态；如果父窗口仍存在但暂时未响应，重新请求数据必须明确是重新拉取结果快照，不是重新分析或写回。
- 结果页优先展示“哪些项目要更新、为什么更新、来源是什么”，避免要求用户在 Jira、聊天记录和 Slides 间反复切换。
- OAuth token 由 Google Slides 页面侧保管，不传入结果页；窗口通信需要校验来源。

## 业内参考

- [Gemini in Google Slides](https://support.google.com/docs/answer/14207419?hl=en) 支持引用 Drive/Gmail 内容、预览后插入，并显示来源；这说明结果页应把来源、范围和插入/写回动作拆开，而不是把 AI 草稿当成最终事实。
- [Google Workspace Gemini sources](https://support.google.com/docs/answer/16813283?hl=en) 明确来源可能不完整或出错，需要用户核对；本功能因此把解析警告和字段来源放在写回前。
- [Google Slides API batch requests](https://developers.google.com/workspace/slides/api/guides/batch) 明确 `batchUpdate` 会先校验所有子请求且原子应用；本功能因此在写回预览、复制清单和失败回执里展示原子批次边界。
- [Copilot in PowerPoint](https://support.microsoft.com/en-us/office/create-a-new-presentation-with-copilot-in-powerpoint-3222ee03-f5a4-4d27-8642-9c387ab4854d) 把生成内容定位为可继续编辑和人工复核的 draft，并通过反馈、来源/凭据等机制处理不确定性；本功能的部分成功回执也应保留人工接管路径。
- [Asana for Google Slides](https://asana.com/apps/google-slides) 通过 smart chips 把任务、项目、目标和状态更新嵌入 slide，说明项目汇报材料需要保留源系统上下文，而不是只写静态文本。
- [Asana Apps Script status report guide](https://developers.asana.com/docs/automate-project-status-reports-with-google-apps-scripts) 与 [Jira reports](https://support.atlassian.com/jira-software-cloud/docs/generate-a-report/) 都强调用任务状态、负责人、截止日期和进度指标生成汇报视图；本功能更偏向“在既有 slide 上审阅并写回差异”。
- [CHI 2022 NB2Slides](https://arxiv.org/abs/2203.11085) 与 [CHI 2023 Slide4N](https://research.ibm.com/publications/slide4n-creating-presentation-slides-from-computational-notebooks-with-human-ai-collaboration) 都强调 slide 生成/整理更适合人机协作而非全自动覆盖；[DraftMarks](https://arxiv.org/abs/2509.23505) 和 [mixed-initiative visual analytics](https://arxiv.org/abs/2509.19152) 相关讨论也支持把来源、修改痕迹和人工判断入口做在结果页里。

- `src/contentScriptGoogleSlide.tsx`：页面按钮、分析流程、结果页通信、应用更新。
- `src/slide.ts`：Google Slides API 读取和写回。
- `src/analyzers/`：表格、文本和 LLM 内容分析器。
- `src/modals/slides-analysis.tsx`：分析结果页和人工确认界面。

- `src/utils/slidesAnalyzerUpdateSuggestions.ts`：从项目分析结果生成字段级更新建议。
- `src/utils/slidesAnalyzerRisk.ts`：风险、阻塞、逾期和否定风险表达的统一判定。
- `tools/verify-google-slides-analyzer.ts`：建议归一化与 Slides 写回请求 payload 校验。
- `tools/verify-google-slides-analyzer-e2e.mjs`：结果页 opener 通信、默认勾选和提交 payload 的扩展 E2E 校验。

## 注意事项

- 写回 Slides 会修改原始文档，需要用户具备对应演示文稿权限。
- Google Slides `batchUpdate` 是批量原子请求；任一请求无效会导致整批失败。
- 本地预检跳过项不会进入 Google Slides API 批次；如果 API 返回失败，结果页不应显示部分成功，而应提示本次没有确认写入。
- 对 visually rich 或非标准布局的 slide，必须保留字段定位、置信度和人工确认，不能把 LLM 结果直接视为事实。
- 若扩展窗口通信失败，重新从 Google Slides 页面触发分析即可。
