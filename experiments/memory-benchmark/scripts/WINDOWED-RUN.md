# E-155 incremental window run

Approved in E-155 on 2026-10-31. This compares **candidate + common raw historical retrieval under an incremental 8h policy**, rather than native full-history ingestion. Raw production text and generated results stay local; do not stage or push run folders, embedding caches, adapter exports, or logs.

The immutable inputs are development golden v1.1 (56 probes at seven as-of instants), source events, model tiers, and the previously frozen 304-event slice. Hashes and implementation hashes are recorded in `reports/run-2026-10-31-8h-v1/matrix-plan.json`. A resumed execution refuses changed data/model hashes. Each cell has a fresh adapter state. Raw bge-m3 vectors can be reused; generated facts, associations, summaries, and answers cannot cross independent builds. Partial or older full-history results are retained separately and never counted as repeat builds.

For each T, native ingestion sees only (T−8h,T]. Earlier raw text is available through a common SQLite FTS5 + normalized local bge-m3 retrieval index, filtered by observed time and exact scope/ACL before ranking. Scene text supplies the query; golden evidence IDs and required facts are used only for scoring and post-hoc regression review. Native and historical rankings are fused with reciprocal ranks, with top-20 and 12,000 UTF-8 bytes per retrieval result. Trace files distinguish native/history/selected IDs and truncation. The context bound applies to retrieved hit text, not whole provider prompts or native internal retrieval. No silent embedding fallback is allowed for this execution.

Consolidation occurs at earlier day boundaries and at T, never at a later day-end before querying T. B decisions are wrapped in a SQLite SAVEPOINT rollback to remove cooldown/outbox mutations between paired probes; A/C/D/E were audited as read-only decisions apart from caches/diagnostics. The bridge fails closed if the current inner adapter layout changes. A uses a process-local bge-m3 embedding client and fresh 1024-dimensional vector tables; production source and user storage remain untouched. Its unused v3 e5 projection may still be populated by native ingestion, but the v3 vector read channel is disabled. Mem0 and Supermemory retain their local bge-m3 implementations; Letta uses its native MemFS plus the common historical channel.

The densest 202-event window is first. Schedule:

1. A→E build-1, all 56 probes each.
2. Each scheme on the same 304-event slice: full native historical processing vs 8h processing + common history. A frozen non-z-ai judge reviews substantive paired output differences, separate from deterministic rubric scores.
3. If numeric control thresholds or judge reviews flag a regression, run uniform 24h and 72h slice diagnostics for every scheme. These have separate labels; original 8h repeats/ablations are skipped rather than treating expanded runs as equivalent repeats. Diagnostics do not automatically establish an expanded-policy winner.
4. Otherwise, build-2/3 and A/B three ablations under the same 8h conditions.
5. Continuous production-mini-7d replay: live and cache runs separately. A cache run requires a completed live run. All actual cache calls remain in the budget.

Exploratory control tolerances: acceptance mean decrease ≤5/100, at most one added acceptance error (F or D below 1, or hard-gate failure), no added permission/future leakage, and no new old-evidence fact omissions. Incomplete pairs do not pass. Difference review and rank stability must be assessed before selecting any winner. Only seven storylines underlie the paired probes; these are not independent statistical evidence of equivalence. The automated summary deliberately never selects a winner. Full 165-day autonomous consolidation, forgetting, long-term profiles, and consolidation-concurrent latency are not established by this policy. Ordinary report latency quantiles are measured; unexecuted latency categories must remain unverified.

Budget is enforced at the proxy as well as before native ingest/consolidation/probes. Guarded requests are serialized so each subsequent call sees settled prior spend. **All preexisting ledger files** count, including failures, smoke validation, fixes, and unattributed costs (the latter count toward total). Unknown/inaccessible policy fails closed. New calls stop below $49 per scheme, reserving $1 beneath the approved $50 cap for an in-flight call. Total ceiling is the lesser of $245 and current ledger total + verified key remaining −$2. This does not alter the OpenRouter key limit or model tiers. The reserve is not a mathematical maximum price guarantee for one in-flight request. Stage allocations reserve remaining funds for controls and replay; budget-limited cells are explicitly skipped/partial. A rejected guard call returns HTTP 402.

`summary.json` includes current coverage, acceptance-only scores (28 expected), paired regressions, actual costs, generation counts, and key usage reconciliation. Native `passed` alone is insufficient: the established scorer can count a zero-scoring legal response as passed, so the paired quality rule uses F/D and hard gates directly. Individual cell reports/adapter exports/traces are retained for review. Matrix failure is not automatically retried; timeouts are recorded. Existing optional spaCy/fastembed warnings in Mem0 remain environment limitations.

Run supervised by launchd label `ai.personal.e155.windowed`; proxy `ai.personal.e155.proxy`, Supermemory `ai.personal.e155.supermemory`, Letta `ai.personal.e155.letta`. Host restart/logout may interrupt launchd GUI jobs; disk artifacts and schedule support manual resume. The launch configuration is local under `.planning/e155-launchd/`. Readiness is demonstrated by its PID, current cell status, and increasing indexing/ingestion progress in cell `cli.log`. Matrix logs are in the new report directory; the superseded full-history run remains in `reports/run-2026-10-31/`.

To stop safely, first set `paused: true` in `.local/windowed-budget.json`, then `launchctl bootout gui/$(id -u)/ai.personal.e155.windowed`. This affects only the experiment; do not kill Multica. To resume, bootstrap `.planning/e155-launchd/ai.personal.e155.windowed.plist` after confirming no old matrix or child remains. Existing completed/failed/skipped cells are not silently repeated.
