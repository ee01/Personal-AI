# Research Notes

- Zapier Help: `Test record`, `Zap History`, and `Zap runs` are separate concepts, which supports visible separation between setup samples and actual scheduled execution. https://help.zapier.com/hc/en-us/articles/8496181725453-Learn-key-concepts-in-Zap-workflows
- Power Automate trigger troubleshooting recommends identifying the specific failed run, checking trigger failures, broken connections, skipped trigger checks, permissions, and run history. This supports placing recovery scope at the action point. https://learn.microsoft.com/en-us/troubleshoot/power-platform/power-automate/flow-run-issues/triggers-troubleshoot
- Google Apps Script installable triggers can call services requiring authorization and run with the authorization of the user who created the trigger. This supports explicit authorization-phase and trigger-owner wording. https://developers.google.com/apps-script/guides/triggers/installable
- Zhang et al., `Helping Users Debug Trigger-Action Programs`, studies end-to-end TAP debugging and notes obstacles users face when moving from incorrect behavior to pinpointing and fixing automation issues. https://www.blaseur.com/papers/imwut22-debuggingtap.pdf
- Manfredi et al., `Toward a Better Understanding of End-User Debugging Strategies`, frames non-programmer debugging of trigger-action rules around mental models and error explanations. https://ceur-ws.org/Vol-3172/short6.pdf
