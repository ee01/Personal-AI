2. **性能与成本改善**：未验证默认回答超时下 `/ask p95` 下降、每日 token 下降、Passive p95 <500ms、Ask 深车道触发率 <20%。没有真实七晚运行记录。
3. **深车道实现差异**：目前是有界确定性拆问、时间词移除/扩展与再次词面检索；没有原方案的小 reranker 和通用深车道多跳。已有亲属边一跳不能代表通用多跳完成。
4. **模型成本路由**：B/C 支持 `RECONCILE_CHEAP_MODEL`，但未设置时沿用主模型；不能把“支持 cheap 配置”写成“默认已使用小模型”。
5. **可见产品体验**：SQLite 回执与操作员 CLI 回滚已实现，原方案提及的 Lens 来源数/跨天回执和一键撤销未落到 UI。本任务 E 阶段目前落 attention 候选；不代表已经在产品中投递提醒。D 的 profile proposal/one-pager 落库也不能代表消费者界面已完整接入。
6. **场景多样性**：注册 case 是匿名合成模板，未达到原方案要求的真实数据脱敏场景覆盖。原始生产只读计数没有证明历史所有 preference 源 episode 未软删。

## 现在可以自己运行的可见对照

在仓库根目录运行：

```bash
memory-service/node_modules/.bin/tsx memory-service/tools/demo-sleep-reconciliation.ts
```

工具只使用内存 SQLite，不读写真实用户库，不调用模型。它运行实际候选生成、shadow runner、真值应用、遗忘与 reader；判决为明确标注的固定 gold，最后在一次性 fixture 显式应用，不能据此绕过生产 live 资格。

你会在终端看到两张中文对照表：

- **状态更新**：先存“Aurora 等待设计”与较新的一手“设计已批准，已开始开发”。整理前同槽召回两条；shadow 后仍两条；fixture 应用后只召回最新状态，旧原文仍存在。
- **远期礼物**：四年前记下“Alex 的女儿喜欢公主角色手办”。模拟遗忘后，主动问“给 Alex 的女儿挑生日礼物”仍能找到偏好；被动面不展示这条归档偏好。

末行 `PASS` 表示这些执行行为已验证。可以修改工具里的消息文本和查询复跑，但固定 judge 不会评估新文本的语义。

## 上线后的人手体验验收场景

下面是待上线、人工资格与开关满足后才适用的检查，不是当前线上已验证结果：

1. 用测试项目录入一条带实际时间的“等待设计”，再录入同项目同状态槽、时间较新的一手“设计已批准，已开始开发”。先确认采集产生了 eligible unit 与正确 subject/predicate。
2. 等待既有 nightly 执行。shadow 阶段只检查判决，不期待答案改变；只有 B live 资格通过且判决应用后，当前状态提问应只引用最新有效值。
3. 打开原来源时间线，旧消息必须仍在。回执应能追踪旧/新 unit 和修订；操作员回滚可另测，Lens 一键撤销尚不可测。
4. 录入偏好与明确“父/母→女儿”关系，确认生成 preference unit。主动礼物提问应命中偏好；年份压力通过隔离工具验证，不需要真的等几年，也不要篡改真实用户数据库时间。
5. 若答案仍混杂旧状态，先查新代码部署、reader flag、shadow/live 资格、eligible 来源、同槽与时间字段、decision 状态及 projection 更新；不能只以自然语言答案表面正确作为全链路通过。
